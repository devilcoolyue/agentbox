[0.1.2 下载与发布说明](https://github.com/devilcoolyue/agentbox/releases/tag/desktop-v0.1.2)：

和 `THIRD_PARTY_NOTICES.txt`。这是独立桌面预发布，不替换服务端稳定版本。

系统凭证库保存/恢复、工作空间列表、共享终端、重连、搜索、字号和主题。
连接从当前桌面集成源码构建的扩展服务端，还支持配对登录、逻辑项目管理、独立 AI/Shell 多终端标签。
下载安装桌面包不会升级服务端；扩展入口按服务端声明的能力显示。
可通过系统文件夹选择器检查本地目录的扫描结果与跨平台名称兼容性。附件粘贴、手动文件传输、同步
预览与持续同步已接入；服务端默认仍为 `sync=0`。管理员可显式配置同步入口，独立恢复记录
与清理按各自能力显示。

服务端和现有网页不依赖本目录。参见[集成计划](../docs/architecture/desktop-client-integration.md)
与[开发验收表](../docs/architecture/desktop-client-acceptance.md)；历史过程见
[实施记录](../docs/architecture/desktop-client-progress.md)。

0.1.2 的 Mac ARM64、Mac Intel、Windows x64 构建与自动化验收，以及服务端兼容、

并发请求合并并补读，退出登录后丢弃旧账号结果。

## 界面与操作

客户端沿用现有网页版的 Agentbox 标识、线性图标、琥珀强调色，以及深色与暖色浅色主题。
左侧选择或搜索工作空间，右侧按“终端 / 文件 / 同步 / 恢复记录”操作；后两个入口由服务端能力控制。
切换功能页与工作空间会保留已打开的项目终端，持续同步也会继续运行。

- 项目行直接提供新建 AI/Shell 终端；设置、移除映射和结束远程终端放在更多菜单中。
- 文件页提供工作区/共享目录切换、目录面包屑和文件下载；上传前会单独确认目标与覆盖范围。
- 终端工具条提供搜索、附件与粘贴；更多菜单/右键可复制、选择输出和暂存输入。
  终端屏幕在两种主题下都保持深色。
- 侧栏“客户端设置”集中管理主题、终端字号、缩放、账号连接、配对、目录检查和版本更新。
  外观默认跟随系统，已保存的深色/浅色偏好继续生效；底栏可直接调整80%～200%缩放。

弹窗支持 Tab 循环、Escape 关闭及焦点返回；繁忙操作和破坏性操作的确认规则保持原有约束。
窄窗口或较高缩放比例使用紧凑导航，并允许文件列表、设置和同步内容各自滚动。

## 开发与构建

开发机需要 Node 22.12+、Rust 1.90+（推荐 stable）、go.mod 指定的 Go 及原生 Tauri 构建工具：Mac 的 Xcode
command line tools，Windows 的 Visual Studio C++ Build Tools/Windows SDK/WebView2。
最终用户不需要这些开发工具。

```sh
cd desktop
npm ci
npm run sidecar
npm run tauri -- dev --no-default-features
```

Mac 开发包：`npm run tauri -- build --bundles app,dmg`；Windows 开发包：
`npm run tauri -- build --bundles nsis`。构建钩子自动生成对应目标架构的 Go 后台。
Mac 使用 ad-hoc 签名，Windows 尚无 Authenticode 签名；没有配置自动更新。

图标由本仓库 `internal/web/static/img/logo.svg` 生成。依赖固定于 npm/Cargo 锁文件。
桌面第三方许可证清单随包生成。正式签名、公证、正式旧包升级、最低系统与物理交互仍是
发布前的验收门槛；未签名包的安装、原生界面和兼容验证范围见开发验收表。

## 连接与边界

- 地址支持反向代理前缀；拒绝 URL 凭证/query/fragment，不自动跟随重定向，不关闭 TLS 校验。
  远程 HTTP 需明确勾选允许，回环 HTTP 可用于本地开发。
- 令牌仅在原生进程及系统凭证库中保存，按规范化服务器与用户隔离；渲染器只保存地址、
  用户名、字号与主题。凭证库失败明确报错，不回退明文。
- 关窗口保留已记住的登录；退出登录先关闭终端，再撤销令牌并删除保存项。撤销失败可重试。
- 旧能力接口返回 404/成功 HTML 时进入基础模式；401、网络错误、5xx、无效 JSON 分别报错。
- 共享终端打开前提示接管，不自动输入命令；正常关闭/额度/授权拒绝不重连，网络故障最多
  退避重试 10 次。旧服务端只显示一个活动共享终端；扩展服务端可同时连接多个项目终端。
- 未确认输出最多 64 KiB，15 秒确认超时；输入缓冲最多 128 KiB，超限粘贴整体拒绝。
  发送失败提示可能部分发送，不重放输入。
- Go 后台提供本地目录预检和握手/ping/shutdown，EOF 取消检查并退出；Windows 使用无控制台进程和 Job Object。
  后台失败不阻止基础终端，可从“客户端设置 → 连接 → 连接诊断”重试。
- 系统剪贴板已接入文本、Finder/Explorer 文件及图片；图片在解码前检查原始大小和尺寸，支持
  Mac PNG/TIFF 与 Windows PNG/DIB，转换后限 19 MiB。真实平台操作、输入法和休眠验收仍待补齐。
- macOS 12+、Windows 10 22H2/11 是待验收候选下限，配置声明不代表实机验证完成。

目录预检和同步基础模块的规则、资源上限、恢复副本与剩余边界见
[desktop-sync.md](../docs/architecture/desktop-sync.md)。检查目录不会建立同步映射，也不会向服务器上传文件。

## 项目模式（扩展服务端）

新版服务端的 `desktop_sync_enabled` 缺省为 `false`，保持已有部署行为。准备试用同步时，
管理员可以在 `config.json` 设置为 `true` 后重启服务，或通过现有管理员
`PUT /api/settings` 提交 `{"desktop_sync_enabled":true}`；客户端重新登录后显示“同步”页。
开关经统一配置校验与原子持久化，修改其他设置不会丢失它。

该设置控制客户端能力发现及新同步计划，不是撤销账号权限或强杀正在提交的文件写入。
停用前先在客户端停止持续同步并处理未完成批次；工作空间鉴权、写租约、条件写入与恢复
记录保护仍独立生效。独立恢复管理不依赖此开关，便于停用后继续核对和导出。

选择空间后添加已有目录的逻辑映射，`.` 是根目录；目录须已存在，映射操作不移动/删除文件。
项目名称可修改；启动参数逐行传入空间所绑定的 Claude 或 Codex，不切换账号或另一种 Agent。
新参数仅影响之后新建的终端。项目目录改变或移除映射前，先结束该项目的所有终端。

“新建 AI 终端 / Shell”创建独立的远程 tmux 资源，多标签可同时连接；工作空间切换保留打开
的标签。关闭标签只断开；“结束”在确认后停止对应 tmux，失败保持“关闭未完成”并允许重试。
自行脱离终端的后台进程可能继续运行。重新连接沿用原终端 ID，不重复启动仍运行的任务。
每空间最多 128 个项目、32 个终端；本客户端最多同时打开 32 个连接（含建立中的连接）。

已登录客户端可生成一次性配对码，另一设备填写相同服务器地址并选择“配对码登录”；码有效期
10 分钟，重新生成会使同用户上一个码失效。配对与 abox-link 隧道开关和码互相独立。

开发服务端首次启动自动将数据库从 schema 9 升到 10。先保存兼容备份；旧二进制不能直接打开
schema 10。已有浏览器/abox-link 接口保持原契约，服务端仍可以独立构建。

新增验证：原生 smoke 脚本加 `--mode projects` 覆盖项目创建和两个独立标签；真实容器测试：

```sh
# 在仓库根目录执行；仅合成数据，无模型请求、凭证或用户挂载。
docker build -t agentbox-client-test:local -f internal/server/testdata/client.Dockerfile internal/server/testdata
AGENTBOX_CLIENT_TEST_IMAGE=agentbox-client-test:local go test ./internal/server -run '^TestClientTerminalsContainerLive$' -count=1 -v
```

该测试使用真实 Docker PTY/tmux，但替代初始化挂载检查且省略网络/MCP hook；不是完整生产
启动、旧发布二进制、服务重启或 purge 验收。

冻结 v0.1.8 源码→当前服务端的独立兼容回归使用 `scripts/test-server-compat.py`，支持
`--browser-smoke`（真实旧网页→新服务端）与 `--desktop-smoke <测试包程序>`（新桌面→旧服务端）。
根目录运行方式和验收边界见[发布与兼容验收](../docs/architecture/desktop-release.md)。
安装探针 `scripts/test-installed.py` 可传 `--previous <真实旧包>`；没有旧包会明确跳过升级部分。

同步后端已有安装身份与本地 SQLite 绑定/基线/未完成操作持久化，以及显式整项目执行器、
私有 IPC 和绑定/预览/确认/取消界面，以及待定批次核对、明确收尾和原内容导出。服务端 sync 仍为 0，正常连接不会显示同步入口。正常服务重启保留身份，备份恢复生成新身份，需重新确认基线。现有“检查本地目录”
按钮仍只预检，不会建立绑定或启动同步；进展和边界见上述 desktop-sync 文档。

## 原生同步与恢复验收

先按上文构建显式 Smoke.app，再在仓库根目录运行（需要 macOS 图形会话）：

```sh
AGENTBOX_SYNC_SMOKE_BINARY="$PWD/desktop/src-tauri/target/debug/bundle/macos/Agentbox Smoke.app/Contents/MacOS/agentbox-desktop" \
  go test -race ./internal/server -run '^TestDesktopSyncNativeSmoke$' -count=1 -v
```

用例启动临时 Go HTTP 服务，真实 Vue 控件通过 Rust 和随包 sidecar 执行同步。验证过期预览/
核对摘要、双向字节传输、丢响应后的 finish、部分完成后的 replan、两端原内容导出、导出拒绝、
取消和退出登录；最后检查真实文件及 SQLite 历史。正常 Go test 默认跳过此用例。

测试配置只编译进 `desktop-smoke`，目录由原生测试配置提供，替代系统选择器的返回值；
不修改真实用户绑定，不向 renderer 开放本地路径参数。仅测试 peer 宣告 sync=1。
本机通过记录为 Mac ARM64；CI 已配置两种 Mac 架构，但未在本轮运行远端 CI。
此 Go 服务端测试包不支持 Windows，Windows↔Linux 端到端验收仍需补齐；不能据此宣布
三平台同步、真实目录选择器或安装包已验收。测试后用普通 `npm run build` 恢复前端产物。

## 同步进度

同步面板现显示阶段、本地扫描文件数、当前相对路径、文件/批次已读取字节及已核验操作数。
字节到达总量之后仍需验证和提交基线，完成与失败以最终提示为准。取消、退出登录或离开
同步空间后，旧任务进度不再更新界面。消息按最新状态合并，并通过原生任务 ID 确认接收，
窗口卡顿不会积累每一次读文件的事件；服务器扫描暂只显示阶段，没有远端逐文件扫描百分比。

原生同步 smoke 已增加慢速分段下载进度和取消后清除断言；只在 Mac ARM64 实跑通过。
正常服务端仍 sync=0，此界面仍由服务端能力控制。完整字段与资源限制见 desktop-sync 文档。

## 解绑与重新绑定

在文件同步面板点击“解除绑定”并确认后，当前文件、旧基线和恢复记录保留，旧绑定进入历史
选项，不能继续同步。“重新绑定此项目”会重新打开系统目录选择器，创建独立绑定；第一次
执行仍需预览并确认，不沿用旧基线。更换目录、项目路径或忽略规则可使用此流程。

服务器身份变化时，列表会标出旧记录，禁止将旧基线用于新实例；旧远端副本不能从新实例
读取。本地历史和仍符合原目录身份的本地副本可查看/导出。若仍有未完成批次，可以恢复原环境核对，
也可以输入固定确认语句归档未知结果；不会回滚文件或把它标成成功。本轮没有自动重新定位移动目录的副本。

本地同步数据库升级为 schema 5，schema 1/2/3/4 自动迁移，旧版 sidecar 会拒绝打开；服务端 schema 不变。
历史页按游标分页并显示逻辑容量，没有自动清理。原本没有恢复引用的已完成历史，在所有远端操作均已
回收后可逐条确认删除本机记录；有原内容引用的批次仍保留审计。Mac ARM64 原生测试已验证解绑、归档副本导出、重绑和新旧记录
共存；Windows/Intel 与真实系统目录选择器仍待实机验收，服务端 sync 继续为 0。

## 原生附件与文件浏览

终端“粘贴”及 Mac Cmd+V / Windows Ctrl+Shift+V 使用系统剪贴板，可读取 Finder/Explorer 文件列表、
截图或普通文本。原生拖入文件、选择文件会先显示附件清单，确认上传后写入旧服务端共享附件 API；
随后可点“插入路径”，不会自动发送回车或执行命令。普通文本粘贴仍走 xterm 的括号粘贴。
单文件最多 19 MiB，选择最多 32 个/总 64 MiB；文件只在原生层打开，renderer 只能用短时单次 ticket。
取消会中止当前请求及后续文件；服务器可能已经收到取消时的文件，不自动重试。
附件沿用服务端现有 48 小时清理规则，长期资料应保存到项目目录。

侧栏“服务器文件”支持工作空间/共享目录浏览和原生保存下载，使用既有 API，不要求开启同步。
手动下载限 64 MiB，完整接收后写入新文件，不覆盖已有路径；支持取消和字节进度。终端“暂存输入”
可编写多行中文后明确插入；组合输入期间延迟字号/布局调整，检测长时间休眠后重连同一终端，
不会重放断线前按键，也不会绕过额度、撤权或共享终端被接管的关闭。

## 目录手动上传与后台同步

“服务器文件 → 上传到此目录…”使用原生选择器逐次选择一个普通文件或代码压缩包。预览展示目标范围、
目录、文件大小、同名项和解压行为；点击确认后重新读取目标目录，发现变化就拒绝旧预览。压缩包使用
服务端既有解压合并语义，明确提示覆盖和部分完成风险；从不发送清空目录选项。旧接口没有条件写入，
最后检查之后仍可能发生外部编辑，也不会生成同步恢复副本。每个文件仍遵循当前 19 MiB 原生选择限制。

持续同步的生命周期现在随登录后的应用会话；切换工作空间后已开启的项目继续检查，任务通过共享队列
依次进入原生 sidecar，侧栏显示状态。取消排队任务不会取消另一个项目的请求，退出登录清除所有监督器。
关闭应用仍停止，不注册系统服务，也不在下次启动自动打开持续同步。


### 本地恢复副本清理

恢复历史中可逐文件确认清理已完成批次的本地副本，建议先导出需要保留的原内容。清理不修改当前
项目文件或同步基线，保留批次、操作 ID 与原内容引用，并显示“原内容已清理”。清理失败后重新加载
历史，可从“清理未完成”继续。未完成、未核验归档、重新规划批次和服务器副本不可使用此操作。
本地状态 schema 1/2/3/4 自动迁移到 5；旧 sidecar 拒绝打开新库。正常 verified 和经完整核验后 finish
的历史均可处理；仅有 started 状态而未确认完成的批次不允许清理。

### 服务器恢复副本与容量

支持清理协议的服务端宣告 `sync_recovery_gc=1`；该能力与 `sync` 独立，正常连接仍受 `sync=0` 门控。
在开发同步面板的恢复历史中，可以查看当前服务器空间的活动操作、旧内容容量和永久执行收据。
每空间限 1000 个活动操作、256 MiB 原内容、100000 份永久执行收据；清理中的操作已预占收据名额。
显示的元数据为逻辑字节，不包含 inode、目录和文件系统分配开销。服务重启后的首次容量扫描可能较慢，
最多 60 秒；无法核验时显示占用未知，不会按零容量继续写入。

先导出需要保留的原内容，再点击已完成批次的“预览服务器清理”。列表最多 1000 项，展示已回收项与
剩余原内容大小；确认后逐项回收。绑定有 pending、历史为 replan/abandoned 或存在未核验操作时拒绝。
操作必须属于原实例、设备和已确认意图；旧服务端不支持时不发送清理请求，服务器身份变化时不发送旧 ID。

回收先记录 `retiring`，再验证并删除原内容，完成后记 `retired`。原 ID 的永久执行收据保留以防重放，
不删除其元数据，只释放旧内容容量和活动操作名额。永久收据到限后不能开启新的回收，之后活动配额
耗尽将停止新增操作。当前项目文件、同步基线和本地副本保持不变；本机 schema 5 保存清理审计。
中断或失败可能已完成部分清理，界面会加载最新历史，必须重新预览后续做，不自动重试。清理中及已清理
的远端副本不再导出。即使原本没有旧内容，也应先回收远端操作，再清理对应的无副本本机历史，避免丢失入口。

这些实现仍不能代替 P3～P5 的完整验收；Windows/Mac Intel 实机、跨版本兼容、签名公证与真实安装升级
仍需完成，服务端继续保持 `sync=0`。

### 本机历史丢失后的服务器恢复管理

支持 `sync_recovery_inspect=1` 的服务器会在空间侧栏显示“服务器恢复记录”，与自动同步入口分开。
可以按原设备 ID 筛选，或每页 50 条查看全部原始记录；记录缺失或损坏会明确标记，不能推断其结果。
“核对记录”显示服务器原执行收据、当前文件与操作前后内容的比较，以及原内容是否可导出。
新本地数据库也能使用该入口，不需要伪造旧设备身份或重建旧批次。

结果不确定的操作只允许核对及导出经过哈希校验的原内容。已执行的操作在没有活动同步租约、
没有本机待定批次引用且内容核验通过时，允许输入“永久清理原内容”后逐条清理；永久收据保留，
当前文件和基线不变。清理前应先导出，并确认其他设备不再需要该恢复副本。失败后重新核对再续做，
不会自动重试或把单条收据显示为整批完成。旧服务端不支持时隐藏入口；服务器身份变化则拒绝操作。

### 界面缩放与终端菜单

底部缩放控件支持 80%～200%，成功后记忆设置。Mac 使用 Cmd +/−/0，Windows 使用 Ctrl +/−/0；
0 恢复 100%，终端字号仍单独设置。组合输入期间暂缓缩放，不把这些快捷键送入远端终端。
右键、终端“更多”或 Shift+F10 打开复制／粘贴／全选菜单，支持方向键与 Escape；Windows Ctrl+C
保留中断语义。文件与截图粘贴仍通过原生受限附件入口，不向网页暴露本地路径读取权限。

macOS 目录预检及同步拒绝外置／网络／磁盘映像／无法核验的卷，也拒绝项目内嵌套挂载到另一卷。
具体判定、性能与实际磁盘映像验证见[卷策略](../docs/architecture/desktop-volume-policy.md)。
