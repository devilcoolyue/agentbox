# M1～M5 开发版人工测试案例

适用本次网页/服务端开发构建。使用新建的测试空间和可公开示例文件，先记录“关于与更新”的服务版本、浏览器与时间。涉及模型的案例由测试者手动发送，会使用所选账号额度；不要在已有重要任务上测试断线或连点。

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| T1 首次引导与权限 | 管理员打开首页“首次使用”，依次进入环境检查、账号和默认模型；普通用户登录后查看可用账号 | 管理员能定位配置入口；普通用户只看到获授权账号，无账号时有明确说明 |
| T2 空项目与首任务 | 新建空项目，核对账号/模型/资源；使用首任务示例，编辑为“创建 hello.txt，内容为 milestone-test，然后说明文件位置”并发送 | 只创建一个空间；可在文件区看到 hello.txt、预览并下载，任务不会在仅点击示例时自动发送 |
| T3 上传与导入恢复 | 创建项目并上传一个含 README.md 的小 ZIP；在导入步骤返回再继续。另用有权限的小 Git 仓库测试导入 | 文件进入同一空间，返回/继续不产生重复空间；无权限仓库出现可处理提示，不自动无限重试 |
| T4 草稿隔离 | 在空间 A 输入未发送文字，切到 B，返回 A，再刷新；切换线程；最后退出登录 | A 草稿恢复，B/其他线程不串入文字；退出后重新登录不恢复已清理的旧草稿。附件需通过有效性检查 |
| T5 双击发送 | 测试空间发送“创建 once.txt，内容为一次发送测试”，快速连续点击发送两次 | 只出现一个已接收回合，不产生两次执行；“使用记录”同一回合不重复扣款（一个回合按模型可有多行） |
| T6 断线后核对 | 测试任务发送后，在浏览器开发者工具切 Offline，再恢复 Online并刷新；不要主动另发相同任务 | 先查询原消息状态，能继续显示或提示待核对；不因断线自动重跑。单纯断浏览器网络不保证出现“结果待核对” |
| T7 搜索与状态 | 给两个测试空间取不同名称，搜索关键词并组合运行/休眠/停止筛选，再清除条件 | 列表符合名称和状态，清除后恢复；停止空间仍能查看原文件和历史 |
| T8 三语与更新说明 | 切换简中/繁中/英文，打开环境检查、设置和“关于与更新” | 标签、错误及操作编号含义一致；服务端、Agent 镜像和桌面版本分别显示。仅查看不会触发升级 |

失败反馈模板：案例编号、服务版本、设备/浏览器、步骤、预期、实际、发生时间、界面操作编号、是否可重复。不要发送账号密钥、完整配置、私有文件正文或原始数据库。

可用样例：`output/manual-test-fixtures/agentbox-sample.zip`，包含一个故意写错的加法函数及测试；任务可填写“修复 calculator.py，让 python3 tests.py 通过，不修改 tests.py”。这是供测试者自行发起的任务。

生产上不通过停 Docker、删除镜像、耗尽磁盘、重启服务或修改真实额度制造故障。上述故障及服务重启/备份恢复已由隔离自动化覆盖；如需要人工演练，另安排维护窗口和测试实例。

M5 桌面三语需要新桌面候选包；已有 0.1.2 安装包不会随服务器升级。正式签名、公证、最低系统/真实 IME、Windows 离线 WebView2 和完整迭代周期试用仍须对应资源，不能由网页测试代替。
