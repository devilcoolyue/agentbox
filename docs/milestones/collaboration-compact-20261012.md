# 紧凑协作工作区与逐步用量

日期：2026-10-12。状态：已发布生产 `v0.1.12-dev.collaboration.20261012.13`，桌面、手机及真实任务只读验收通过。

## 页面与交互

协作详情占满当前聊天工作区，将原来连续堆叠的轨迹、输出、最终结果、交接记录和文件变更收进四个标签：**过程、步骤输出、最终结果、文件与记录**。固定的简短顶栏和标签栏保留当前定位，过程页只让时序图自己的视口滚动，其余标签各自滚动。独立协作面板使用同一布局，配置和需要用户处理的操作保留独立入口。

默认显示过程，不因轮询切走用户正在看的标签。最终结果入口始终可见，完成后增加提示标记；点击轨迹中的“查看步骤输出”会切换到对应输出标签，并选中实际步骤。切换任务、关闭详情或离开空间继续清理旧读取代际与回放，避免旧任务的响应进入新任务。

时序图改为紧凑行，时间、参与者泳道、Token、费用和耗时在同一行对齐。默认合并同一实际步骤的派发、启动和结束等状态事件，保留决策、真实交接、提问、返工、验证和交付等关键事件；“展开全部事件”可查看完整轨迹。搜索仍检索完整事件集合。合并只改变展示，不删除或重写持久事件。

活动角色、沿实际连线运行的光点与新事件进入动效表达当前工作状态，历史节点不会因轮询重复入场。隐藏标签、关闭详情和减少动态效果设置会停用相应动效。

## 用量来源与边界

逐步用量由服务端 `step_usage` 提供，依据现有用量账本归集到真实的协作步骤与回合。Token 和费用不根据输出长度、总费用比例、默认模型价格或图形动画推算；派发、开始、交接等同一步骤的多行事件不会重复记为收费。缺少用量时显示未记录或待结算，部分用量保留不完整状态，不以零替代未知值。

Token 总计包括输入、输出及缓存读写字段，决策模型单独说明。Jev 决策费用单列，总费用包含决策费用；不把 Jev 的费用摊到某个执行步骤，也不将未知的决策 Token 补为已知。点击步骤可查看输入、输出、缓存读取、缓存写入及结算状态。

回放只冻结和展示已有事件，不重新执行 Agent、不调用 Jev、不提交任务操作。当前 `step_usage` 账本没有历史结算快照，因此回放时隐藏当前结算和费用，不把后来完成的结算显示成早先就已知的数据；返回最新后恢复当前账本数据。固定底栏提供带播放图标的“时序重放”按钮，支持暂停和拖动，播放键设置明确无障碍名称。

纵向间距仍表示事件顺序，不能据此推断执行时长。耗时只使用实际已记录的起止时间。模型决策仍在原有配置冻结时进行，不因页面动画在每次派发时重新调用 Jev。

本次修改不新增调度能力。后端仍为两个角色的串行协作及既有答疑、返工分支；页面中的动态连线不代表多个执行 Agent 已支持并行运行。账号权限、费用扣除、预算、验证和结果应用规则保持原有约束。
