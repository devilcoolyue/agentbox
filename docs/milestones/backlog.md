# 后续实施单元（第一轮 M2～M5）

第二轮 M6～M10 的实施单元见 [roadmap-2.md](../roadmap-2.md#实施单元)；本表保留第一轮口径。

[原计划](../roadmap.md)的必做范围和验收保持不变。以下为仓库内可独立审查的工作项，尚未创建外部 Issue；每项完成后将实现和实际证据写入对应里程碑记录，不以本表的描述代替完成状态。

| 编号 | 交付 | 验收重点 / 依赖 |
| --- | --- | --- |
| M2-01 | 按角色和环境状态的首次使用引导 | 管理员环境/账号/默认模型串联；普通用户只见授权账号；无账号不提交必败表单；复用 M1 诊断 |
| M2-02 | 空项目、上传、Git 三种创建/导入入口 | 返回/重试复用已创建空间；上传失败与 Git 认证失败可恢复，不能留下多个半成品容器 |
| M2-03 | 最终账号/模型/资源确认和首任务路径 | 显示实际采用的配置；可编辑任务例子；连到文件、变更审查、下载/推送 |
| M2-04 | 三种更新对象的版本与生效范围 | 服务端/Agent 镜像/桌面更新明确区分；兼容状态和空间重启要求可见；沿用更新器 |
| M2-05 | 三语、键盘、触屏及目标用户验收 | 管理员/用户/无账号/导入失败回归；5 名目标用户观察，建议 4 人在 10 分钟内无指导完成，须按 M1 样本校准 |
| M3-01 | 按实例/用户/空间/线程隔离草稿与待确认内容 | 过期、禁用本机保存、退出清理、附件有效性；不串用户或恢复不存在路径 |
| M3-02 | 持久接收、客户端 ID、确认与状态查询 | 同一 ID 只启动一个回合，确认丢失先查询；能力协商兼容旧客户端 |
| M3-03 | 明确的回合生命周期与不确定结果恢复 | 区分待接收至完成/中断/待核对；断线不等于失败；服务重启未知状态不能自动重跑；用量账本事务不变 |
| M3-04 | 空间名称搜索及运行/休眠/停止筛选 | 100 空间合成数据，按约定设备测量；保留最近空间与线程搜索 |
| M3-05 | 消息可靠性矩阵 | 双击、断网、丢确认、刷新、多标签、线程切换、退出重登、服务重启；不重复执行/扣款 |
| M4-01 | 依据 M2/M3 热点拆分聊天/设置与后端执行编排 | 初始化、取消、销毁归属清楚；业务服务不依赖 HTTP 包；不按行数机械拆分 |
| M4-02 | 错误/聊天契约与多端兼容窗口 | 延续 M1 v1 样本，增加协议版本/能力/淘汰规则、Go/TS 一致性与冻结旧客户端回归 |
| M4-03 | PR、Linux 集成、发布完整验收三层 | 沿用统一入口与 CI；定向 race、每个缺陷的行为回归、固定 runner 耗时及连续 20 次稳定性记录 |
| M4-04 | 候选 CLI 的行为闸门 | 握手、续聊、中断、用量、MCP 合成冒烟；未知格式/握手失败不能切换；自动跟随也过门槛 |
| M4-05 | 升级、备份恢复、回退与恢复目标 | 干净 Linux 升级/重启/系统和完整恢复；真实 systemd 与模拟分别记录；schema 拒绝降级；明确数据规模、RTO/RPO 与文件备份范围 |
| M5-01 | 正式签名、公证、旧包升级与应用内更新 | Apple/Windows/更新签名分开验收；keyring、目录绑定、同步基线和恢复记录延续 |
| M5-02 | 最低系统及真实设备场景 | IME/拖放、多屏/DPI、休眠、安全软件、无 WebView2 离线 Windows；不能只用 CI 构建推断 |
| M5-03 | 独立桌面三语版本及多端说明一致 | 另行交付桌面包；统一状态/错误/版本解释，保留各端适合的交互 |
| M5-04 | 自愿同步试用与稳定发布门槛 | 至少完整迭代周期、退出条件和版本组合记录；管理员显式开启；未解决数据丢失/越权/重复扣费/启动失败阻止稳定版 |

M2-01～M2-04 已实现并通过本地自动化（见 [M2 记录](m2.md)）。M2-05 的真实触屏与 5 名目标用户验收仍待外部资源；[M3](m3.md) 已接入草稿、待确认副本、持久接收确认和核对界面，空间搜索筛选及联合可靠性矩阵已通过，性能设备/阈值待确认。[M4](m4.md) / [M5](m5.md) 已启动，聊天/设置生命周期、业务编排、契约、候选 CLI 闸门、真实 systemd 恢复自动化与桌面多端一致性已交付；固定本机 Linux runner 20 次已通过；恢复目标及桌面外部验收尚未完成，开发版交付见[记录](delivery-20261005.md)。M1/M2 的软件基础与本地合成验收不替代[真实观察与资源准备](observations.md)；维护者仍需指定评审/观察/签名资源负责人。

排期仍保留原计划每期 2～3 周和约 25% 回归/反馈时间。自动编码和缓存测试的耗时不能换算成人员排期，也不足以缩短用户观察或试用周期；待实际评审速度、M1 样本及设备/证书资源明确后再重估，不编造新的交付日期。
