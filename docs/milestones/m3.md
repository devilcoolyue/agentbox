## M3-01 当前交付范围

- `/me` 提供按实例和用户创建身份隔离的草稿范围，复用已有实例身份文件。正常重启身份保持，备份恢复到新实例重新生成；读取身份失败只关闭持久恢复，不阻断登录。
- 新网页显式请求稳定的空对话上下文；无正文的元数据事件让草稿所在空对话可以重新选择，重复创建空对话仍复用。不会生成用户消息、模型任务或用量记录；首次真正发消息的标题逻辑继续使用用户消息计数。
- 提取 `features/chat/draft-store.ts` 与 `drafts.ts`：浏览器 7 天保存、按页面独立写入、会话存储只记指针、容量拒绝而非静默驱逐、存储失败保留输入。关闭保存清除副本，退出清理身份范围；同浏览器另一页面改变登录会使旧页面退出且不删除新页面的 token。
- 上传捕获空间/线程代际和取消信号，切换后迟到结果不得写入新输入框。恢复和发送前由受限文件句柄校验附件，拒绝链接、目录、越界和失效路径；输入/附件在检查期间变化时不自动发送新内容。旧服务端无校验能力时，恢复的附件须重新上传。
- 未发送文本现在可在空间/线程切换、刷新和多标签间按归属恢复。现有发出后清空输入的路径仍待下一单元改为持久接收/确认；没有把相同文本的广播当作确认，也未宣称幂等发送或扣款验收通过。

开发验证：存储层五组行为测试、Go 范围/空线程/附件边界及定向 race 已通过。主网页检查发现新增按钮缺少图标后已修复。早期过期夹具在仍打开的页面修改时间，会被页面关闭时正常保存覆盖，已改为离开应用后模拟过期；沙箱 iframe 的测试语言注入已加顶层来源检查，不把夹具错误当成产品存储故障。

## M3-02/03 持久存储基础（2026-10-05）

- schema 12 新增 `chat_requests`，冻结输入/选项/附件引用/线程/身份范围，生成稳定 turn ID。用户创建身份、空间和请求 ID 组成去重键；相同 ID 的并发请求只向一个调用者返回 fresh=true，改变任意输入字段冲突。每空间 accepted/starting/running/uncertain 最多一条。
- 状态推进使用修订号；不能跳过执行阶段声明完成，running 出错不能直接写成安全失败。重启将未结束回执改为 uncertain，显式 reviewed 才释放存储层准入，保留未知原因且旧 ID 永不再次获得 fresh=true。放弃未知 ID 持久化围栏，与迟到接收在同一数据库事务边界竞争。
- 运行 SQLite 连接改用 WAL + synchronous=FULL，替换连接仍应用 FULL。空间/用户删除在原事务内清空回执正文并保留围栏；原用量写入与额度扣减事务未变。
- 服务初始化在 Docker 连接前恢复回执，初始化后续失败也不会把旧 accepted 记录留成可重放任务。尚未增加消息 API 或 chat 能力通告，也未修改旧 WS 执行路径；这些基础不能替代完整发送/重复执行/计费验收。
- 新增合成回归覆盖多连接并发、输入冲突、状态 CAS、重启旧执行者拒绝、核对与放弃、用户重建、写入故障/删除事务，以及 schema 11→12 保留创建收据、用量与账本。子进程在已提交 WAL 后直接退出、不关闭数据库，验证恢复为待核对；它不等于物理断电测试。系统/full 备份回归保存输入、状态、turn ID 和围栏，full 的 Docker 停写检查仍为注入桩。

下一步接入 HTTP 接收/查询、旧 WS 与线程操作共用准入、执行器阶段及原用量收尾，再接浏览器待确认副本和用户核对入口；线程删除清理及附件生命周期需随接入补齐。当前本地验证结果记录在下方，整项仍未完成。

## M3-02/03 服务端协议接入（2026-10-05）

- 独立 `chat_protocol:1` / `chat_scope` 能力及属主限定 PUT/GET/POST 回执接口已接入；见[协议](../chat-protocol.md)。新请求先冻结并持久化，同 ID 查询/重放先于账号与额度再准入；changed payload、scope、thread 或失效附件明确拒绝。消息 ID 与错误关联编号分开。
- `chatReceiptTurn` 观察原回合路径，沿用原 workspace/credentials/usage 服务，稳定 turn ID 贯穿转录与用量。阶段提交失败不启动模型；最终回执在原用量 flush 和转录/目录同步后提交。用量事务失败、历史失败、输出流错误或缺少明确 provider 结束信号均保持 uncertain；没有第二套模型执行或计费路径。
- `agent.Adapter` 提供结构化终结状态，Codex app-server 翻译保留 interrupted 标识，不靠错误文案判断用户中断。传统 exec 补查 Scanner 错误；用户在 app-server 握手期间中断后不再走 exec fallback。用户中断与服务关闭分开，带 ID 的中断不能打到后续回合，重复动作不重复发送 SIGINT。
- 旧 WS 和线程新建/激活/删除共用持久准入。GET 发现无执行者的活动回执时保存 uncertain，不自动派发；review 使用修订号并保留原未知原因。线程删除先清回执正文留 ID，再删除文件；空间/用户删除沿原事务。附件 TTL 与接收共用互斥，逐条读取回执引用，错误时不清理。
- 新增七个兼容错误码与中/英/繁体文案、Go/TS 结构定义和构建产物。尚未改网页发送、待确认副本或核对界面；M3-01～03 整项与 M3-05 浏览器可靠性矩阵仍未完成。

合成 Docker HTTP/exec fixture 驱动实际服务端执行路径，覆盖并发同 ID 只执行/扣款一次、忽略接收回复后按 ID 查询、账号撤权后读取原结果、内容冲突、未知结果阻止旧 WS/线程切换、revision 核对、用户中断/服务关闭区别、重复中断只发一次信号、丢失执行者、scope/属主/附件/写 token 边界、阶段持久化失败不执行、用量事务失败不误报成功，以及线程删除与附件保留。fixture 没有真实 CLI/provider，不消耗模型额度，不替代真实 Docker/设备验收。

## M3-01～03 浏览器待确认发送与核对（2026-10-05）

- 新增 `features/chat/outbox-store.ts`、`outbox.ts` 和 `local-identity.ts`。v1 能力下发送先冻结内容/选项/附件并保存副本，再移出输入框；可继续编辑新草稿。默认存储失败不发请求，明确关闭保存后仅保留页内副本。网页只在能力缺省/0 时兼容旧 WS；未知显式版本、协议错误或网络失败不降级重发。
- 查询、刷新、联网恢复和新页面不自动提交；明确重试也先查询原 ID。同 ID 回执核对空间/线程/输入/修订，旧修订、相同文字广播和不匹配回执不能清副本。状态区显示冻结设置，提供查询、原消息重试、放弃、结果核对、中断和复制回输入框；跨对话复制须确认，已有输入不覆盖。
- 7 天后删除本机待确认正文/附件副本，保留查询标识以围住迟到请求。原文和引用从服务端回执恢复时重建附件元数据并复查；失效引用继续禁发。本机保存开关和退出覆盖两类副本，服务端已接收任务不会因本机清理而取消。
- 迟到成功/失败只能更新原空间记录，不覆盖新空间输入或投递提示；退出关闭本功能确认框。持久清理由发起身份切换的页面执行，延迟恢复的旧页面只忘记内存/指针，不删除同一用户新登录后的副本或新 token。活动状态不会被上一回合的历史回执覆盖；轮询保留展开状态与键盘焦点，普通点击不强制聚焦。
- API 增补 `pending_only=1`，轮询只取当前活动回执，不重复下载最近 50 条正文；默认列表行为不变，schema 仍为 12。原用量、额度及执行路径未另行修改。

## M3-05 联合可靠性矩阵（2026-10-05）

`test-chat-integration.mjs` 构建并启动真正的 `cmd/agentbox`，通过浏览器真实登录/会话/历史/附件/回执 API 与 WebSocket 驱动原执行器。唯一模拟边界是独立的 Docker/CLI 输出端：收到的命令不会实际执行，app-server 握手在回合前结束，沿生产代码的安全 exec 回退产生可控合成输出。fixture 独立计数实际进入执行流的请求，再读取真实 SQLite 回执、用量、额度及账本核对，不用浏览器状态冒充执行或扣款证据。

`integration.chat` 在本机运行；`docker.chat-reliability` 交叉构建真实 Linux 二进制，使用独立测试卷和桥接网络、仅发布随机回环端口。服务端跨重启固定同一端口/浏览器 origin，测试只终止/重启自己的进程或容器。没有挂载 Docker socket、读取已有实例数据或运行模型。权限保持原样：非 root macOS 附件上传实际收到 chown 拒绝并明确记录为成功上传不适用；Linux root 服务端完成真实上传、删除和失效引用恢复。测试权限不通过放宽生产 Chown 获得。

| 场景 | 联合结果 |
| --- | --- |
| 双击、HTTP 与 WS 确认同时丢失 | 浏览器保留原 ID/正文；实际服务端已运行，刷新不自动重发 |
| 两标签并发重放 | 同一冻结请求从两页并发 PUT 12 次，只有一次执行和一笔扣款 |
