## M2-01：角色引导与账号准入

- 首页新增可折叠的首次使用指南。首次没有自己的空间时展开；创建首个空间后回首页收起，仍可重新打开，不替换最近空间列表。
- 管理员可从指南进入 M1 环境检查、已有账号接入窗口和默认模型设置。环境状态来自实际诊断，显示的是本次登录中的最近一次观察，不凭点击动作或配置文件存在标记模型可用。
- 普通用户只看到已授权账号和相应 Agent 的默认模型，不出现实例检查/配置按钮；没有授权账号时明确联系管理员。管理员没有账号时给出账号配置入口。
- `GET /api/onboarding` 是只读、按身份过滤的配置快照，返回版本、可配置/可创建标记、本人是否有空间、授权账号的必要字段和默认模型；不返回账号 env、凭证、代理、其他用户的空间数量或授权名单。
- `can_create` 仅表示存在已授权且支持的账号。凭证存在是准备提示，不验证外部登录、模型权限或余额，不给既有手动 CLI 登录/自定义接入增加新的执行限制；服务端原准入检查仍生效。
- 创建弹窗的请求与生命周期提取到 `features/workspaces/create.ts`。打开和提交前均重新读取账号；只拥有 Codex 时自动选 Codex，禁用无账号的类型。账号读取失败不能退回缓存数据继续提交。
- 撤权后不静默替换账号发起当前创建。快速重复提交只保留一个在途请求；取消/关闭后的旧读取不能覆盖新弹窗；退出时清理创建草稿、账号选择和指南数据。创建的文件系统失败沿用 M1 脱敏错误。
- 首页引导订阅既有导航事件，使返回首页后的准备状态及时刷新。

M2-01 当时仅实现快速提交保护；随后 M2-02 的持久创建/导入恢复见下节。没有自动发送模型任务或部署服务。

## M2-02：三类项目来源与恢复

2026-10-05 开发版新增 schema 11 创建/导入收据。用户可选择空项目、压缩包/多文件/目录上传或 Git；导入发布到新目录，不覆盖已有内容。协议与行为边界见[创建空间与导入项目](../project-creation.md)。

- 创建先持久预留 ID/默认模型，再按 workspace 生命周期锁准备目录，最后同事务发布空间、Git 默认绑定和收据。重复提交、响应丢失和正常进程重启复用同一 ID；参数不符拒绝。删除/放弃保留重放阻止记录，用户重建按创建身份隔离。
- 上传复用受限文件/归档校验，暂存于容器挂载外，校验所有文件合计大小和 Linux 属主后不覆盖发布。Git 复用原容器执行、连接授权及操作审计；不引入宿主 Git 降级。
- 导入尝试单独记账（不涉及费用账本）：running/uncertain 阻止新尝试，重启残留标为 uncertain；用户查看文件并明确 review 后才能继续。不把网络错误推断为回滚，不自动重跑未知结果。
- 网页在发送前保存按实例/用户身份隔离的会话指针，保留必要创建参数但不保存文件/Git URL/凭证；刷新/返回可恢复流程，退出清理本机表单与指针。已成功导入的确认丢失不会再上传或克隆。
- 独立 PUT 路径避免旧服务端忽略 request_id，旧 POST 仍兼容原客户端。schema 10 的旧二进制不能打开 11，回退需兼容备份，未部署或迁移生产。

验证：Store 并发/事务回滚/身份隔离/重启/未知结果/放弃围栏、HTTP 创建并发与删除、上传路径/ZIP/合计大小和不覆盖重放、Git 认证失败重试与摘要冲突通过定向回归；相关 race 通过。Linux root 创建/上传与 UID 1001 真实 chown 拒绝通过。最小 Alpine 镜像缺 git-http-backend 的 Git 用例明确跳过，随后在现有 Debian Agent 测试容器中通过；这使用测试执行器，不冒充完整生产 Docker 链路。

网页三语 × 两角色已覆盖创建确认丢失、上传失败复用、Git 认证失败、成功确认丢失后的刷新、不重跑未知结果和手动核对。重新启用父 fieldset 后显式同步自定义 select，避免恢复流程后控件仍禁用。

## M2-03：配置确认与首任务交付路径

- 创建弹窗显示账号、空间模型、新容器 CPU/内存/进程上限；收据返回后使用实际保存的模型。读到的模型或资源与原展示不同则保留同一空间并暂停导入，用户核对后继续。普通用户获得的是三项资源白名单，没有网络、挂载和凭证。
- 模型是空间保存值；资源是当前给新容器的设置，容器创建时生效，已有容器保持原值。此处没有改变资源生命周期，也不把配置值称为既有容器的实测上限。
- 新创建空间自动展开首任务引导；示例按本次导入目录或通用 `/workspace` 生成，只在点击后填入对话框。用户可以编辑、切换模型并自行发送；有输入时保留原文。现有空间默认折叠，引导和目录提示在退出时清理，不新增持久内容存储。
- 查看文件固定进入当前空间工作区；下载也明确固定为工作区 ZIP。Git 路径引导用户审查、提交后从原「远程」入口确认推送，不绕过既有授权/确认，不自动提交/推送。顺带修正文档中仍写“远端操作仅终端”的旧说明。
- 已通过后端字段白名单/已保存模型/当前资源及定向 race；三语两角色覆盖配置变化暂停、复用原空间、示例不自动发送/不覆盖输入、工作区下载范围。窄屏以键盘打开示例并编辑、显式发送，合成 WS 验证任务正文与实际选中模型，只有这一明确发送产生一轮模拟请求。真实模型和真实远端任务没有执行。

## M2-04：三类更新对象与生效范围

- 管理员「关于与更新」展示服务端、Agent 镜像、桌面应用三类对象，分别说明版本来源、兼容状态、重启范围与原更新入口。原“客户端更新”改名为“Agent 镜像更新”；最近任务的 CLI 版本明确标为任务起点与目标，不冒充所有运行中空间的版本。
- 新增管理员只读 `GET /api/updates/components`：当前构建/schema、配置镜像 ID/版本标签、服务端桌面协议和同步开关。限时 3 秒读取 Docker 元数据，失败不暴露原始错误，读取中配置变化丢弃旧版本；不访问发行/npm 源，不构建/拉取镜像或运行 CLI，不启停空间。
- 页面不把版本比较或镜像标签当作兼容证明：服务端候选仍由原升级预检核对配置/数据库，CLI 协议及真实模型调用仍需单独验收，网页不能读取本机桌面版本。服务端自动升级只做系统备份的限制有明确提示。
- 桌面源码的「关于与更新」展示实际桌面版本及本次登录能力，区分未连接/基础模式/协议 1/未知协议；更新仅重启应用，服务端和空间无需重启。本项不改变原生更新器、自动检查偏好、安装确认或签名逻辑，已发布桌面包需独立升级才会获得界面改动。
- 修正设置页资源说明：镜像变更在停止再启动后采用；资源上限在容器创建时生效，不能承诺重启既有容器就会刷新。截图发现的窄屏标题语言滞留改用绑定渲染，补同页三语切换回归。
