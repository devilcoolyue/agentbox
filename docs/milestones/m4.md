## 边界与契约

后端执行器不导入 server 或 HTTP/WS 包，通过窄 Docker 接口及回合专属回调接入。app-server 只有回合提交前失败才可 exec 回退；回退前再次检查取消/用户中断，不支持的选项不能被静默丢弃。环境解析在每次 Docker exec 前调用，撤权不能变成无凭证继续执行。历史、用量结算和最终回执顺序沿用 M3；现由 `Service.Run` 调用窄 Runtime/Observation 接口编排，room/server 继续管理准入与房间释放。

`ChatHistory` 只拥有加载请求与定时器，不拥有 composer 或 DOM。prepare 完成后重新检查代际与空间 ID，再允许应用历史；超时后即使传输迟到成功也拒绝渲染。取消清理期限；轮询替换相同 ID 的空间对象不会使请求失效。返回结果保留代际检查，避免异步收尾修改后来的视图。

`contracts/chat-errors-v1.schema.json` 是本轮新增接口的字段/类型/状态契约，`scripts/generate-contracts.py` 生成 `web/src/contracts/v1.d.ts`。`npm run test:contracts` 拒绝遗忘生成；Go 测试对照真实结构体的 JSON 字段与状态枚举；TS 测试检查全部状态、空正文围栏、错误身份/修订/附件/未来状态。契约版本不增加数据库版本，本批仍为 schema 12。HTTP 的旧 `error` 字符串及旧 WS 路径保留。
