# 协作减重：直接执行、评审证据和增量交接

日期：2026-10-12。状态：已发布生产 `v0.1.12-dev.collaboration.20261012.15`，数据库 schema 16。发布与生产核验记录见文末。

## 本轮交付范围

在已有可靠接收、单活动步骤、独立工作副本、费用结算和显式应用机制上增加两种冻结策略：

| 策略 | 模型步骤 | 验证与交付 |
| --- | --- | --- |
| `workflow: {version: 1, mode: "direct"}` | 仅执行者，可在一个 CLI 回合内自行探索、修改、测试；必要提问直接交给用户 | 平台验证，失败或剩余工作可在限额内返回执行者修复；无需独立规划和模型评审；结果仍待用户显式应用 |
| `workflow: {version: 1, mode: "reviewed"}` | 规划 → 执行 → 模型评审，以及必要答疑/返工 | 评审前冻结同一快照的差异和平台验证证据；验证失败不能批准交付 |
| 无 `workflow` 的旧请求 | 原有三阶段行为 | 原请求、指纹和已持久化的步骤输入保留原语义 |

主辅、CLI、账号、模型继续由用户配置，经济档或强档不是角色身份。直接执行使用执行者配置，协调者绑定仅作兼容占位，不创建其参与者、home 或容器，不进行其模型选择，也不要求其账号可用。实际执行者仍须通过账号授权、模型和推理档位检查。`decision.roles.coordinator` 在直接执行下必须为 `fixed`。

页面在既有团队设置中选择策略，支持服务端 `options.workflow_version=1` 能力发现；旧服务保留旧发送路径。已有任务的策略不能通过重新配置改变。发送前冻结的策略参与请求指纹核对，刷新/失联继续查询原 ID；不能将“直接执行”的回执解释成“协作复核”。直接完成明确显示未做独立模型评审；没有验证命令时也不声称测试通过。

## 评审材料

服务端通过已登记的基线与当前快照生成 `review_evidence`，在调度评审前持久化，后续执行使用已冻结的输入。材料绑定两个快照 ID、清单 SHA-256、计划版本及完整变更清单摘要，不依赖工作副本当前状态或恢复 `.git`。

证据包括新增、修改、删除、权限和链接变化；文本使用多段 unified diff，省略未变化的大段内容。每文件最多读取 256 KiB、diff 最多 24 KiB，总 diff 最多 64 KiB；清单最多 256 项，完整证据最多 192 KiB。二进制、超大文件、复杂度或总预算超限分别标记原因，保留变更/缺失数量，不把未显示内容当作未修改。

评审提示要求优先根据差异判断，再读取必要的当前文件。规划线程中的旧文件内容不能覆盖当前快照证据。重要变化证据不足时必须说明缺失，不能只看部分 diff 即批准。当前保持同角色原生线程续聊，没有声称“所有评审开新线程更省钱”。

计划新增可选 `code_map`：相对路径、符号、作用、约束、可选短摘录。最多 32 个路径，每项最多 16 个符号、8 个约束，摘录最多 2048 字节；非法路径、重复路径及超限被拒绝，旧计划格式仍可读取。这些是模型提供的导航材料，不授予额外权限或证明文件仍未变化。

## 增量交接与恢复

新策略按参与者代际和原生线程保存上下文确认边界。只有原步骤正常结束、历史/费用收尾、进程停止和交接成功后推进；队列已接收、响应丢失、执行结果不明都不能冒充处理完成。同线程不重新回送自己的已确认输出；新参与者重建必要上下文。

有界材料保留用户要求、答复、未决问题、有效计划及约束和最新相关结果/评审。可省略的历史细节显式标记数量和引用；必要材料无法容纳时暂停为 `context_limit`，不静默裁掉用户约束。平台验证结果仍随修复/评审步骤提供。

schema 16 增加参与者上下文确认字段和评审证据持久结构。迁移只新增版本，不改已使用的 013～015；不修改历史费用。恢复到新实例清除原生线程确认边界，旧实例的缓存/线程不会被当作可继续使用。升级前需要兼容备份；schema 15 二进制不能直接打开已迁移的数据库。

## 费用与后续边界

直接成功路径减少的是独立规划/评审两个模型回合，不保证一次 provider 请求即可完成，也不保证某个固定省钱百分比。一次 CLI 回合仍可包含多次工具调用和模型请求。

Jev 本轮仍只在首次配置冻结前选择实际模型，不自动决定策略、不在每次工具调用时重选。自由委派工具桥、跨角色动态子任务、并行执行者、自动能力升级，以及按成本/缓存选择全新评审线程，仍属于后续工作。

对照实验应固定任务、源代码基线、验收标准、模型/强度与价格依据，分别记录经济模型单独执行、强模型单独执行、协作复核，以及未来按需委派的成功率、人工修复、完整耗时与所有尝试费用。缓存比例只以输入为分母；账本费用、供应商实际支付与订阅额度分开说明。历史上只跑过协作的任务不能推算未执行路线的反事实费用。

本轮已增加[只读账本对照工具](../collaboration-cost-comparison.md)：使用独立 SQLite 备份和显式实验清单，将所选编码回合与 Jev 决策费用按策略汇总，包含已记录的失败尝试；不执行模型、不重定价、不从 completed 推断独立验收通过。普通聊天按属主、空间、线程和回合精确归因；协作继续按原参与者代际关联。自动标题、终端调用等明确排除，未知费用/耗时保留缺失状态，不输出节约百分比。
