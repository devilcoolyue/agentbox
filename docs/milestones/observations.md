## 观察安排

组织负责人、参与者和可用时间待维护者提供。每位参与者使用匿名编号，先确认服务、账号和测试项目准备情况；若这三项尚未准备好，记录为环境准备失败，不混入“上游正常条件下的首任务耗时”。真实模型任务由参与者在获准使用的测试实例执行，自动验证脚本不会代为发起付费请求。

统一任务：登录 → 创建空间并导入一个可公开的示例项目 → 发送可编辑任务 → 查看改动 → 下载结果或确认 Git 推送。先让参与者自行操作，记录首次需要帮助的位置；人工提示的时间与内容类别单列，不把提供口头引导后的结果算作无指导完成。

每条记录应包含：

| 字段 | 填写口径 |
| --- | --- |
| 观察编号、匿名参与者编号 | 如 O-001、U-01；当前没有实际编号记录 |
| 版本与入口 | 服务端版本/提交、网页/桌面/abox-link 版本、是否代理访问 |
| 角色与设备 | 管理员/普通用户、系统版本、浏览器、视口、输入方式；不记录真实账号 |
| 前置条件 | 服务/账号/模型/示例项目是否已准备；诊断中未检查的项目保持未检查 |
| 时间 | 登录后开始创建/导入、首个可见模型输出、完成查看/下载的时间 |
| 结果 | 完成/未完成/中止，是否需要口头提示 |
| 失败类别 | 配置、Docker、镜像、授权、额度、磁盘、WS、上游、导入、界面、未知 |
| 定位过程 | 首次失败时间、首次有效原因/动作时间、操作编号、处理结果 |
| 支持成本 | 求助次数、处理分钟数、是否需要管理员参与 |
| 备注 | 只记录操作和现象，不附提示词、代码、凭证、文件内容或原始数据库 |

首任务耗时 = 完成查看/下载 − 开始创建/导入。定位耗时 = 首次得到可执行原因/动作 − 首次失败。模型上游延迟与本地启动耗时分别看，不从小样本推导整体改善比例。M3 的 100 空间性能阈值需用明确设备/浏览器和这些观察校准，尚未约定具体毫秒指标。
