## S1-09：在线升级兼容与存量安装迁移（待补）

2026-10-11 追加核对：生产 `v0.1.12-dev.storage.20261011.4` 的升级 helper `status` 实际返回 `supported=false`，原因是“正在运行的服务与发布安装不一致，请使用手工升级”。`deploy/update.py:probe` 拒绝所有非空 `DropInPaths`；本次配额加固添加的 `agentbox.service.d/storage.conf` 正好触发该条件。这是本次改造引入的升级兼容缺口，前述运行验收未覆盖它。

- 待修复：升级器识别并严格校验产品生成的存储附加单元及实际生效属性；继续拒绝未知的服务改写，不能简单删除 DropInPaths 检查。
- 待补门槛：目标二进制必须声明并验证当前 storage_policy/tool_storage 所需能力。现有兼容检查仅核对配置可解析、数据库 schema 与 compatibility epoch，旧二进制可能忽略新存储字段；开发版也允许切换到较早的最新正式版，不能仅靠版本号或 schema 当成存储兼容证据。
- 当前旧实例升级只会替换程序、备份状态、重启；不执行选盘、复制校验、ext4 配额初始化、swap/Docker 停启或旧容器挂载重建。`storage-config` / `storage-prepare` 仍是操作员离线命令，本次生产迁移使用了针对该实例的维护流程，尚非通用页面迁移器。
- 后续设计：普通升级保留旧布局且不自动启用存储策略；迁移另设管理员预检与计划，选择已有目标盘、显示受影响服务与所需容量、备份校验后才执行。不得猜测磁盘或自动格式化；需持久化步骤、支持中断恢复，确认迁移完整后才退役源目录。
- 验收：已有 storage.conf 的生产同布局一键升级成功；未知附加单元和缺少存储能力的候选被拒绝；普通旧布局升级继续可用；迁移流程另做真实文件系统/容器挂载及失败恢复验证。未完成前不宣称支持一键完成存储迁移，也不将当前开发包视作已对外发布。

## S2：S3 备份（后续）

- 保持活跃文件和 SQLite 在 POSIX 数据盘；S3 用于备份和不可变对象，不直接挂载为 `/workspace` 或 SQLite 存储。
- 选择与服务器同地域、经过实测的 S3 兼容服务；桶私有，服务身份最小权限，容器不持有桶凭证。使用加密与独立版本，明确流量/请求成本、保留期、密钥恢复和 RTO/RPO。
- 对接现有备份命令与清单校验。系统备份和完整用户备份分别标识覆盖范围；现有 `--full` 要求停服并检查 Docker 挂载，不宣称在线一致的用户文件备份。
- 分片上传可重试、取消和回收残片；记录完整性校验值，不把 multipart ETag 当成文件 SHA-256。云端验证成功后才按策略轮换本地备份。
- 验收：上传中断、凭证失效、校验失败、下载中断、恢复空间不足；从云端恢复到新目录并启动隔离实例，核对用户文件、凭证、历史和账本。只有上传成功不算完成。

S2 本身不释放活跃空间占用。桶连接设置必须走 Config 的校验与原子持久化；凭证不出现在网页响应、日志、对象名称或仓库中。

## S3：空间归档与恢复（后续）

先手动归档/恢复，验收后再开启自动策略。候选初始策略是“停止且 7 天未使用”，可配置并支持固定本地；该策略当前未启用。

1. 增加独立、持久化的存储状态：本地、归档中、已归档、恢复中及失败信息，不复用容器 running/stopped。
2. 归档占用空间读写准入，协调聊天、终端、网页文件、Git、上传、桌面同步、凭证及后台写入。仅停止容器不构成一致性保证。
3. 项目及持久 home 写入独立版本对象，清单验证成功、数据库持久记录后才删除本地副本。对象身份包含实例、用户创建身份、空间及版本；跨用户授权与同名重建隔离必须验证。
4. 恢复先预留解压容量、限制并发，下载到私有暂存目录，校验路径/哈希/属主/权限/链接，成功后原子发布，再播种当前授权账号凭证并启动。旧 home 凭证不得参与向当前账号池反向同步。
5. 聊天索引与小体积历史首期保留本地，网页仍可查阅；首次文件操作/终端/对话触发恢复，并显示进度与失败重试。等待请求共用一个恢复任务，不重复启动或提交模型回合。不承诺零等待。
6. `/shared` 被同一用户多空间引用，附件还受聊天回执引用保护，首期独立留在数据盘，不随单个空间归档删除。不能通用排除 node_modules、私有模块或 SDK；只剔除已明确可重建的缓存。

验收必须覆盖任意阶段服务重启、重复任务、删除与恢复竞态、撤权、磁盘满、对象损坏/丢失、存储暂时不可用和符号链接攻击。上传失败保留本地，恢复失败保留云端；故障后无“数据库已归档但没有完整对象”的状态。

归档可能是唯一有效副本，不能按对象年龄自动删除。数据库备份引用的归档版本必须纳入保留图；仅清理无人引用且超过宽限期的版本。归档与独立备份分开，避免用户删除或实现错误同时摧毁所有副本。需要即时恢复的对象不进入深度冷存储。

## S4：多节点（长期候选）

只有单节点瓶颈得到测量后再设计调度、节点健康、空间独占租约与 fencing、跨节点恢复、元数据及凭证协调。S3 只是对象载体，不提供空间执行互斥；禁止同一空间在两节点同时写入。目前不引入 Kubernetes 或分布式数据库，不将本项计入 S1～S3 的完成标准。
