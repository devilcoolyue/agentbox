# 协作事件轨迹与派发时序

日期：2026-10-11，验收完成于北京时间 2026-10-12。状态：已发布 `v0.1.12-dev.collaboration.20261012.12`，生产页面验证通过。

## 页面行为

协作详情将固定阶段图改为由持久事件生成的轨迹。用户、决策、主 Agent、辅 Agent、平台各有独立泳道；派发、模型选择、澄清答复、计划交接、执行结果、退回修改、评审与交付按实际事件顺序出现。连线方向来自平台记录的发送者和接收者；排队步骤表示平台已派发，不代表模型已接收。

页面提供“派发时序”和“事件列表”两种视图，可搜索事件、查看详情，并从关联步骤打开已保存的输出。运行中的角色显示活动状态，新事件沿实际连线出现动效；轮询保留已有节点，避免重复播放历史事件。

“历史回放”冻结当前事件集合，支持暂停、拖动位置和返回最新。回放只在浏览器展示已有记录，不重新提交任务、不运行 Agent，也不调用 Jev。尚未到达回放位置的结果不会提前显示为已完成；模型正文保持原文，不增加翻译或总结调用。

## 数据与能力边界

轨迹按事件先后排列，纵向间距不表示调用耗时。时间标注使用已记录的事件时间；回合结束后可使用已记录的起止事件计算回合经过时间。未记录的 Jev 请求耗时、API 首字时间或置信度不补造。历史模型标注按对应配置版本读取，不能套用后来修改的角色配置。

本次改动是执行过程的可视化，不改变后端串行调度、账号权限、预算、决策冻结、结果评审和交付验证。动态连线或回放动效不表示多个 Agent 已能并行运行；真正并行调度需要单独设计隔离、冲突处理与验收。

主要实现：`web/src/features/collaboration/workflow.ts` 与 `trace-model.ts`，聊天协作详情和独立协作面板共用。
