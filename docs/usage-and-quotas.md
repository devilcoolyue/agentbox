# 使用记录、价格与额度

[返回文档目录](README.md) · [项目首页](../README.md)

## 三种“额度”分别是什么

| 信息 | 来源 | 用途 |
| --- | --- | --- |
| 账号订阅额度 | provider 的订阅查询 | 查看账号侧可用情况，与 provider 的限制相关 |
| 使用记录中的 token / 费用 | CLI 回合事件或终端 transcript | 核对 agentbox 能观察到的消耗 |
| 用户剩余额度 | 管理员充值和本地扣减账本 | 决定该用户是否可继续发起新任务 |

给 agentbox 用户充值只改变本系统账本，不会给模型服务商账户充值。用户余额充足，也可能碰到 provider 的速率或订阅额度限制。

## 记录范围

**一行 = 一次模型请求**（一条 provider API 响应），也是扣额度的单位。回合里 CLI 每调一次工具就再请求一次模型，每次都把整段上下文重新发送（大部分命中缓存），所以一个回合会连着好几行，共享同一个回合 ID，类型下方标「第 3/27 次」。子 Agent 与主模型的请求同样各成一行；起标题与下一步提示是单独的类型。

按回合合并时缓存读取会逐次累加、远超模型的上下文窗口，也对不上 provider 的逐次计费，所以不再合并。网页对话的首字与总耗时按回合测量，只记在回合的第一次请求上，其余行显示「—」；终端行每次请求各有一份按 CLI 日志估出的耗时（见下文延迟列）。

升级前的 Claude 网页对话是按回合合并保存的：这些行已按整行扣过款，账本每条流水都带当时的余额，拆开会破坏账本，所以保留原样，类型下方标「合并 N 次」。终端补记只记账不扣额度，升级后重新扫描时历史记录会自动拆成逐次请求，沿用原价格，金额不变。Codex exec 回退路径只有回合合计，仍是一行。

| 来源 | 用量如何取得 | 费用如何取得 | 是否扣用户余额 |
| --- | --- | --- | --- |
| Claude 网页对话 | 消息流与本轮新增 transcript，按 message.id 去重，每条消息一行 | 回合开始锁定价目表，逐条计价 | 已开启计量且有价格时扣减 |
| Claude 起标题 | 独立、不续聊的 CLI 收尾事件 | CLI 报价；未报正费用时可按表折算 | 已开启计量时扣减 |
| Codex 网页对话 | app-server 每次模型请求的累计用量差值，每次一行，中断/失败回合也计；回退到 `codex exec` 时取 CLI 收尾事件 | provider 不报价，逐次查价目表 | 已开启计量且有价格时扣减 |
| Codex 起标题 | CLI 收尾事件 | provider 不报价，需查价目表 | 已开启计量时扣减 |
| Claude 终端 | 扫描 CLI transcript，每次请求补记一行 | 按价目表折算 | **不扣减** |
| Codex 终端 | 扫描 codex-tui rollout，每次请求补记一行 | 价目表折算 | 不扣减 |

终端记录通常在 CLI 写完一次回复后约 1 秒内入账；使用记录页和终端顶栏「本空间已花」开着时，服务端在用量入账后推送变更，页面随即刷新，推送断开时退回定时刷新。另有每分钟扫描和查询页面时请求的异步补扫作为补充。页面请求不等待扫描完成，扫描状态只反映补记进度，不表示 CLI 已写完全部用量。长回合可能先显示部分消耗，再更新同一行；这不是实时请求账单。

使用记录与 CSV 的思考强度来自当时的记录：网页对话读取聊天回执；Claude 终端读取 assistant transcript 的 `effort`，Codex 终端读取 `turn_context.payload.effort`。终端强度随用量保存，不使用当前账号或 CLI 配置倒推历史。同一回合、同一模型的调用若缺少强度或出现不同档位，该行不显示单一强度；起标题和缺少回执的旧网页记录也留空。

升级后会重新扫描现存空间的终端日志，已有用量行可补齐强度，不增加重复记录、不扣余额，也不替换首次保存的价格。原始日志已删除、旧 CLI 没有记录强度或格式无法识别时，历史强度无法恢复，继续留空。

费用在数据库和 API 中使用整数微美元：**1 USD = 1,000,000 micro USD**。导出、接口接入和充值时应确认单位。

Claude 网页对话不使用 `result.modelUsage` / `total_cost_usd` 扣款：这些字段在续聊时可能累计整个 provider 会话。借鉴 [cc-switch 的消息去重](https://github.com/farion1231/cc-switch/blob/846de29c13ac4d65f164db8c15dd5fd58e29f972/src-tauri/src/services/session_usage.rs#L601)，同一消息 ID 优先保留有 `stop_reason` 的记录，同等完整度选输出 token 较大的记录。流式 `message_delta` 和 transcript 用于补齐输出，普通 `assistant` 事件可能仍是占位值。

回合启动前记录 transcript 文件边界，结束时仅读取本 provider 会话及子 Agent 的新增记录，排除历史和终端来源。路径通过 safefs 访问，拒绝链接、替换与截断。消息 ID 按工作空间持久去重，去重凭据、按模型汇总的用量与额度扣减同事务写入；服务重启或消息重放不会再次收费。缺失完整记录时只采用实际观察到的消息用量并记录读取错误，不退回会话累计值；中断或 CLI 未写完日志可能导致用量不完整。

schema 9 迁移不重算旧记录，也不自动调整旧余额。历史累计误记需要单独审核原始事件并同步冲正账本，不能直接对全库相邻行做差（旧 CLI 也存在单轮口径）。

### 离线修正历史累计误记

`scripts/repair-claude-cumulative.py` 使用独立的、修正前 SQLite 备份副本作审计基准，默认只读预览。仅当同一 provider 会话的模型累计差值与本轮顶层四类 token 完全一致时，才修正为增量；费用先按原口径转整数微美元再相减，不用当前价目表重估历史。重复 result 需所有模型用量相同；已有 `refund:turn:` 冲正会抵扣应退金额，避免再次退款。不能证明的记录列入 `unresolved`，保留原账。

```bash
python3 scripts/repair-claude-cumulative.py \
  --original-db /安全备份目录/original-state.db \
  --db /var/lib/agentbox/state.db \
  --report /安全备份目录/preview.json
# 核对报告并停服务后，使用新报告路径加 --apply；执行成功再启动服务。
```

应用时必须先取得 `agentbox.lock`，整个修正在同一数据库事务内提交。原始 raw、价格快照和原扣款流水均保留，退款/舍入修正追加幂等 `adjust` 流水；余额和累计入账/出账按当前额度建立时间之后的流水核对。报告文件不覆盖旧文件，应用后再次预览应没有待修改行。运行前保留并验证系统备份；首次处理还应在备份副本演练。合成验证：`python3 scripts/test-repair-claude-cumulative.py`。

## 查看与筛选

从侧栏打开「使用记录」。普通用户只看自己的记录；管理员可查看和筛选全部用户。

- 默认范围是**系统时区的当天**，重置也回到当天。
- 页面可以按用户、Agent、模型、类型和时间筛选，筛选可选值由服务端在权限范围内生成；API 还支持按空间 ID 筛选。
- 时间弹窗先编辑草稿，点击「确定」才应用；取消或点外部放弃本次修改。时分留空时按起始 `00:00`、截止 `23:59` 处理。
- 快捷范围包括当天、昨日、最近 24 小时、7 / 14 / 30 天和全部时间。
- 勾选跟随当前时刻后，可见页面每 30 秒更新；相对范围滚动两端，自定义范围只移动结束时间。
- 默认每页 20 条，可切换 50 / 100 条；列表独立滚动，合计与分页常驻。

时间展示、筛选和 CSV 都采用 `config.timezone`，不随访问者电脑的时区变化。页面结束分钟包含该分钟；服务端查询使用开区间截止，前端会加一分钟。

表头合计属于**整个筛选结果**，与当前页无关。CSV 导出同样按筛选范围，但单次最多 500 行；超出时缩小时间范围分批导出。

对话开启「委派」后，跑腿模型的消耗以「委派跑腿」类型显示，记在发起委派的原工作空间下（跑腿在隐藏的跑腿空间里运行时也一样），费用详情与 CSV 带委派 ID。类型筛选中的「对话」只列主 Agent 自己的回合；委派时的 Jev 判断仍是「决策调用」，同样带委派 ID。跑腿用量与普通对话走同一结算路径、同一事务扣额度，不额外记一笔委派总额；对话里的委派卡片显示该次跑腿的已结算费用。

明细的「缓存命中率」= 缓存读取 ÷（未缓存输入 + 缓存读取 + 缓存写入）× 100%，显示一位小数。输出 token 不参与分母；有输入但未命中显示 0.0%，没有输入显示“—”。CSV 使用相同口径。

### Token 列怎么读

参照 sub2api：第一行 ↓ 是输入（未命中缓存）、↑ 是输出，给完整数字；第二行蓝色是缓存读取、黄色是缓存写入，按 K / M / B 缩写（一位小数，例如 236.2K、6.8M），为 0 的桶不显示。悬停或聚焦旁边的 ⓘ 可看四个桶与合计的完整数字。顶部合计卡片同样缩写，悬停显示完整值；CSV 一律导出完整数字，并带「回合内序号」（如 `3/27`）和「合并请求数」两列。

此前版本的 Codex 网页对话只记了回合内最后一次请求，调用过工具的回合少记了大部分用量；这些旧记录与相应余额不追溯修正。

## 费用与延迟怎么读

计费方式显示在费用附近：

| 标记 | 含义 |
| --- | --- |
| CLI 报价 | 独立起标题或历史 Claude 行的 CLI 估算成本，不代表订阅账号实际扣款 |
| 价目表 | 使用系统中的单价按 token 折算 |
| 未定价 | 没找到单价，只记录 token，费用为 0 |

Claude 网页对话与终端行按价目表 / 未定价显示。独立起标题报告 0 费用时沿用价目表补算行为；旧记录没有来源快照，仍按旧规则推断标签。

点击费用旁的 `?` 打开明细，可查看输入、输出、缓存读取、缓存写入各自的 `token × 单价`，以及实收金额。

新记录的明细单价取自**入账价格快照**，包含命中的模型/Agent 键、普通/长上下文单价与阈值；修改价目表不会改变历史单价。升级前按回合合并的 Claude 网页行保存 `per_request`：逐请求判断价格档位并舍入到微美元，再汇总，明细中标准单价的参考拆分可能因档位或舍入不同而与实收有差异。旧记录没有快照，显示明确标注的当前参考价，不能据此还原原始定价。CLI 报价只有总额，按表分项只是参考拆解。

### 每次请求的实测计时（Claude Code）

Claude 空间里的 CLI（网页对话与终端都算）会把每一次 API 请求的计时经 OpenTelemetry 报给 agentbox：**首字** = 从发出请求到收到流的第一个事件（`message_start`），**耗时** = 从发出请求到流结束；请求出错重试时只算最后一次。agentbox 按请求 ID 把它记到对应的那一行，延迟列显示「首字 X / 耗时 Y」，不带「≈」。这是 CLI 在实时流上自己量的数：对 Claude Code 2.1.303 + Opus 5.5 实测，它与流事件实际到达的时刻相差在几十毫秒以内。

- 网页对话行收到实测计时后同样按单次请求显示；回合级的首字与总耗时（从容器就绪算起，含 CLI 启动与工具执行）移到悬停说明里。
- 收不到遥测的行照旧：网页对话显示回合级计时，终端行显示下面的日志估算值。
- 遥测靠 CLI 启动时读到的环境变量开启。升级后新发的网页对话立即生效；终端里已经开着的 shell 沿用旧环境，要新开一个 tmux 窗口（或重启空间）再启动 `claude` 才会上报。
- 账号环境变量里已经配了 `CLAUDE_CODE_ENABLE_TELEMETRY` 或 `OTEL_*`（管理员自己的收集器）时不注入，这个账号的请求只有估算。接收端的地址见[配置说明](configuration.md)的 `usage_telemetry`。
- Codex 暂未接入遥测，仍用日志估算。
- 只取 `api_request` 事件里的请求 ID、首字与耗时。同一批导出里的其他事件（提示长度、工具决策、账号属性等）解析后即丢弃，不落库、不写日志；Claude Code 默认也不导出提示词与回复正文（显示为 `<REDACTED>`）。

**输出速度** = 输出 token ÷（耗时 − 首字），即首个事件之后的生成速度。输出 token 含思考，所以它比肉眼看到文字出现的速度高。实测值显示为「N tok/s」；输出不到 100 token 或生成不到 0.5 秒时不计算，因为几十个 token 常常在首个事件之后一下子到齐，算出来的数说明不了快慢。

### 回合计时与日志估算

没有实测计时的网页对话行：延迟列中的「首字」与「总耗时」都由 agentbox 从容器就绪后计时，包含 CLI 启动时间，是整个回合的数据，只显示在回合的第一次请求上，其余请求显示「—」；这种行不计算输出速度。老记录没有墙钟总耗时时显示 provider 自报的「模型」耗时，口径不同；升级前同一回合按模型拆成的多行会重复这些耗时，不能把它们相加。

没有实测计时的终端行显示**这一次请求**的估算值，前面带「≈」。终端流量不经过 agentbox，只能按 CLI 日志的时间戳推算（做法参照 [cc-switch 的会话日志计时](https://github.com/farion1231/cc-switch/blob/f92ff0b03964188f1cd011d9302ab8869d7a8219/src-tauri/src/services/session_usage.rs#L206)）：

| | 起点 | 首字 | 结束 |
| --- | --- | --- | --- |
| Claude 终端 | Claude Code 2.1.302 起发请求时记下的 `api-request` 时刻；更早的版本取上一条用户消息或工具结果写下的时刻（跳过 attachment），略早于真正发出 | 回复以思考块开头时，用它写完的时刻减去 `thinkingDurationMs`；以文字或工具调用开头时推不出 | 这条回复各内容块写下时刻中最晚的一个 |
| Codex 终端 | 这次请求第一个输出项之前最近的用户/developer 消息、工具结果、`turn_context` 或上一次 `token_count` | 0.16x 起 `item_completed` 记录的思考/回复项开始时刻（`started_at_ms`）中最早的一个；一开头就调工具时推不出 | 0.16x 的 `token_usage_record`；旧版取 `token_count`，它等工具跑完才写时取最后一个输出项 |

耗时不在 100 毫秒～1 小时之间、首字不落在耗时之内、回复还没写完或日志里找不到起点时不显示，延迟列为「—」。估算行的输出速度显示为「≈N tok/s」：推出了首字时与实测同一算法（输出 ÷（耗时 − 首字），门槛同为 100 token / 0.5 秒）；推不出首字时只能用输出 ÷ 整个耗时，含首字等待、偏低，只在输出不少于 200 token、耗时不短于 1 秒时估算。同一次以思考开头的请求，日志估算为首字 1503 ms / 耗时 12668 ms，CLI 实测为 1502 ms / 12696 ms；以工具调用开头的请求推不出首字，耗时少算约 0.1 秒（最后一块写下时流还没结束）。

升级后重新扫描现存终端日志时，历史终端行会补上耗时与首字；原始日志已删除的旧行仍显示「—」。CSV 的「首字ms」「总耗时ms」两列对终端行即这一次请求的估算值；「请求首字ms」「请求耗时ms」是 CLI 实测值，没有时留空；「输出速度tok/s」优先用实测，没有时用估算，保留一位小数，算不出时留空。

## 管理价目表

在「系统设置 → 模型管理 → 价格」维护四个桶的单价，单位为 **美元 / 百万 token**（旧地址 `#/settings/pricing` 会跳到这里）。保存会提交整张表，因此删除一行也会使其之后不再用于定价。价格目录（远程地址、自动检查与跟随、差异预览）收在表格下方的折叠卡片里，标题行显示来源与检查状态，检查失败或执行「检查更新」时自动展开。表格默认「只看在用的模型」：只列各账号可用模型、默认模型、现有空间和最近 30 天用过的模型实际命中的行，其余行隐藏但照常保存，取消勾选即可看到全部。

同一页的「账号模型」标签页在每个模型旁显示它实际命中的单价，兜底价和未定价标成警示色，点开可以只改这一个模型的价格或让它跟随价格目录；改动与这里是同一张表，「价格」标签页有未保存的编辑时会先要求保存或放弃。

价格查找顺序：

1. 精确模型 ID。
2. 去掉 `-YYYYMMDD` 日期后缀的模型系列名。
3. Agent 名 `claude` / `codex` 兜底。
4. 都没有则按 0 记录，不扣款。

Codex 的用量事件可能没有模型名，`codex` 兜底价格应与实际使用模型保持一致；如果不同账号使用不同价格模型，一个 Agent 兜底无法精确代表所有账号。

下例只演示字段与计算，**不是官方最新价格**：

```json
{
  "pricing": {
    "codex": {
      "input": 5,
      "cache_read": 0.5,
      "cache_write": 0,
      "output": 30,
      "long_context_over": 272000,
      "long": {
        "input": 10,
        "cache_read": 1,
        "cache_write": 0,
        "output": 45
      }
    }
  }
}
```

例如 1,000 个未缓存输入 token、2,000 个缓存读取 token、100 个输出 token，按上例短档计算为 `$0.005 + $0.001 + $0.003 = $0.009`，入账 `9000` 微美元。

长上下文阈值按「未缓存输入 + 缓存读取」判断。**超过阈值后，这次请求的四个桶都使用 long 档**，不是只给超出部分加价。新记录一次请求一行，按每次请求分别判断；只有合计的行（如 `codex exec` 回退）按整行判断。阈值和价格需要按实际 provider 核对。

价目表支持独立价格目录、检查更新、差异确认、自定义价格保护和最近 10 次版本回退。现有价格升级后默认作为自定义保留；手动修改模型单价后转为自定义。目录检查不会直接调价，网页回合与自动起标题在调用 CLI 前锁定价格。内置旧快照标为尚未重新核验，远程目录需自行配置可信 HTTPS 地址。详情见[价格目录维护](pricing-catalog.md)。

## 用户额度与充值

管理员在「系统设置 → 安全与访问」的用户列表中打开「额度」，选择模式、充值并查看最近流水。

| 模式 | 是否扣账本余额 | 余额 ≤ 0 时 |
| --- | --- | --- |
| 不限额 | 不扣，用量继续记录 | 正常使用 |
| 只计不拦 | 按已定价网页消耗扣减 | 正常使用 |
| 超支拦截 | 按已定价网页消耗扣减 | 拦截新网页回合与终端接入 |

没有额度记录的新用户默认不限额，不等于余额为 0。开启计量后再充值；恢复不限额会移除额度状态并保留账本记录，后续重新启用的余额应重新核对。

充值流水有幂等引用：同一个 `ref` 重试不会重复入账。API 推荐用 `micro_usd` 整数，例如充值 10 美元传 `10000000`，负数用于冲正，示例见 [API 文档](api.md)。

## 拦截边界

网页回合开始前检查余额，结束后才知道实际费用。把余额花到负数的这一轮会正常完成，下一轮再被拦截；自动起标题在余额不足时直接跳过。

终端接入前检查一次，连接期间每 30 秒复查。如果网页对话把余额扣完，终端连接会随后关闭；关闭网页终端只是断开 tmux 附着，**不会强杀已经运行的 CLI**。

由于 Claude / Codex 终端补记都只记用量、不扣余额，当前额度功能不能作为完整的硬预算控制。账本扣减与网页用量写入在同一事务内完成，但使用记录总费用可能包含不扣余额的终端行，因此不一定等于余额减少量。

### Codex 终端补记

扫描 `<home>/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`，仅接受 `session_meta.originator=codex-tui`，排除 exec/app-server；来源字段存在时需为 cli/tui，或 0.160 起 TUI 改跑在 app-server 上后写的 vscode（网页对话同样写 vscode，但 originator 是 agentbox，不会混入）；独立的 subagent rollout 不作为主终端流水纳入，避免将来源不明的后台记录重复计入。以 task_started/turn_started 或 turn_context 的 turn_id 归并，按模型分行。利用累计 token 差值跳过重复的 token_count/额度通知；缓存输入从总输入中扣除，reasoning 不再次加到 output。缺少可信来源、回合 ID 或累计用量的记录不猜测补账。

watch 覆盖日期目录，周期全量扫描兜底；扫描同一个文件、进程重启或记录继续增长不会新增重复回合。去重键含工作空间、provider thread、turn 和 model，复制到另一个空间不会覆盖原空间记录。终端记录首次入账保存价格规则，续写按该规则重算该行；无价的首次快照仍保持未定价。历史无快照的终端行，未变化时保留原费用，增长时继续按旧规则折算并标明参考价。

补记只记账，不改变余额。解析按固定 Codex 0.145.0 的公开结构与合成样本验证，不承诺所有未来 CLI 格式或缺失/截断历史都能恢复。
