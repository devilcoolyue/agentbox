# 创建空间与导入项目

[首次使用](user-guide.md) · [M2 进展](milestones/m2.md) · [数据库升级](architecture/database-migrations.md)

当前开发版的创建窗口提供三种来源，均先确认账号授权，再创建一个可复用的空间。该功能尚未发布；创建收据由 schema 11 引入，当前开发源码已继续增加 schema 12 聊天回执存储。首次启动会升级至当前 schema，升级前需保存并验证备份，见[数据库迁移](architecture/database-migrations.md)。

## 三种来源

| 来源 | 操作 | 完成后的入口 |
| --- | --- | --- |
| 空项目 | 选择 Agent、账号和名称后创建 | 对话；不会自动发送任务 |
| 上传项目 | 选择 ZIP/TAR/TGZ、多个文件或本机目录，再指定工作区中的新目录 | 文件页，先检查导入结果 |
| 从 Git 导入 | 选择已有 Git 连接、填写仓库地址和新目录；可进入 Git 管理修正连接后返回 | 变更页，沿用原有仓库发现和审查 |

上传保留压缩包内部结构和目录的相对路径，目标为 `/workspace/<项目目录>`。目录名不能以点开头或包含路径分隔符。目标必须不存在，不清空或合并已有目录。文件先在容器挂载外完整暂存/校验，再以不覆盖重命名发布；Linux 必须能设置容器属主 `1000:1000`。上传总文件字节不能超过 `max_upload_mb`，一次最多 2000 个上传文件；压缩包展开另受现有解压数量/体积限制。

Git 继续通过容器里的 Git、原授权与操作审计执行。它可能启动该空间的容器，并按既有账号/额度规则准入，但不调用模型。连接认证失败后可修正连接并在同一个空间重试，不重新分配容器/空间。新入口没有宿主机 Git 降级路径。

## 失败与恢复

创建第一次发送前，网页在会话存储中保存请求编号和必要创建参数。服务端持久接收后固定空间 ID、默认模型与所选默认 Git 连接；相同编号、相同请求只对应同一空间。确认丢失时先查询状态，刷新后也可继续。账号、Agent 和名称在接收后冻结；修改这些信息应明确放弃流程并重新开始，已创建空间仍保留，可从列表继续查看或删除。

每次导入有独立尝试编号，服务端保存输入摘要及结果。已完成尝试重放只返回原结果，不能覆盖其后编辑的文件；同编号携带不同输入会拒绝。已知失败后再次导入使用新的尝试编号，但仍复用原空间。

如果服务在发布/记回执之间重启，或无法确认文件是否发布，结果保持 **待核对**。这时：

1. 点击「查询状态」，不要把断线当作失败。
2. 使用「查看已有文件」核对空间内实际目录。
3. 确认后点击「已核对，允许继续」。这只解除未确认操作的阻塞，不删除、回滚或重写文件，也不把历史状态伪造为成功。
4. 可选择空项目继续使用现有空间，或选择一个尚不存在的新目录重新导入。已有目录始终不会被覆盖。

「放弃流程并重新开始」不会删除空间或文件。即使先前请求尚未到达，服务端也会保留放弃记录，阻止迟到的旧创建请求再分配空间。删除空间同样保留收据 tombstone，旧请求不能复活它。

文件内容、Git URL、密码和 Token 不进入浏览器会话存储。刷新后未完成的文件上传需要重新选文件，未保存的 Git URL 需要重填；已确认成功的导入不需要重传。退出登录清理本机指针和表单，服务端按当前用户的创建身份提供未完成列表；删除后重建同名用户不会继承旧记录。会话存储不可写时不发送新的创建请求，以免丢失恢复编号。

收据记录的是操作结果，不保证后续文件没有被编辑、移动或删除。备份恢复也可能回退数据库/文件历史；不能把本协议解释为跨任意备份回滚的“永久恰好一次”。系统备份包含收据和元数据，项目文件仍需完整备份。

## 配置确认与首个任务

创建窗口展示选中账号、空间默认模型，以及新容器的 CPU、内存和进程上限。打开窗口读取当前设置；取得创建收据后改用空间实际保存的模型。如果返回的模型或资源上限与用户刚看到的不一致，会保留空间并暂停在确认窗口，用户核对后再次点击继续才导入项目。不会为了配置变化另外创建一个空间。

模型在预留空间时保存；之后管理员更改全局默认模型不会修改它。资源上限与模型不同：**这是当前系统给新容器的配置，并非已运行容器的实测值或每空间冻结值**。Docker 创建容器时读取当时的设置，已有容器沿用自己的上限；创建窗口到首次启动之间管理员仍可能调整设置。页面明确标注此边界，不把全局配置当作既有容器的状态。

首次完成创建后，以三步浮层依次高亮任务输入、文件和变更入口；支持上一步、下一步、跳过及 Escape 退出，并遵循系统减少动态效果设置。点击「编辑任务示例」将一个可修改的文档任务放入对话框：本次导入流程会带上项目目录，空项目和刷新后的通用示例从 `/workspace` 开始。已有输入会保留，示例不会自动发送；用户可以调整任务和对话中的模型后自行发送。

引导将查看工作区文件、Git 审查和下载串在一起。下载固定为当前空间的工作区 ZIP，不受此前共享目录选择影响。Git 用户在「变更」逐项审查、提交，再从「远程」选择连接/分支/目标执行推送；没有仓库也可以直接查看和下载文件。引导不会自动提交或推送，也不会把点击入口标为任务已完成。

引导不占据工作台布局。浏览器按实例/用户记住已展示状态，跳过或完成后，新建其他空间和刷新均不重复弹出；已有空间从“更多操作 → 使用指引”主动打开。存储不可用时仅在本次登录内记住，不影响正常使用。项目目录提示只在当前登录页面内保留，退出时清理；引导不保存任务正文或账号令牌。

## 协议

所有接口需要当前登录。收据按用户名和用户创建身份隔离，管理员不能读取他人的创建记录。

| 接口 | 行为 |
| --- | --- |
| `GET /api/session-creations` | v1 能力发现、本用户 `actor_key` 及最近 50 个未完成流程 |
| `PUT /api/session-creations/{request}` | 幂等创建；32 位小写十六进制请求编号，参数冲突拒绝 |
| `GET /api/session-creations/{request}` | 查询已接收请求、空间是否存在、忙碌标记和最近导入记录 |
| `POST /api/session-creations/{request}/upload?attempt_id=…&directory=…` | `multipart`：`mode=archive/files`、`files`，文件模式另有对应相对路径的 JSON `paths` 数组 |
| `POST /api/session-creations/{request}/git` | `{attempt_id,connection_id,url,directory}`；复用原克隆链路 |
| `POST /api/session-creations/{request}` | `{action:"finish"/"abandon"}`，或 `{action:"review",attempt_id}`；运行中/未核对导入不能被悄悄跳过 |

创建状态为 `reserved/ready/complete/abandoned`；导入为 `running/succeeded/failed/uncertain/reviewed`。导入响应 HTTP 200 表示已取得操作状态，不能仅据 HTTP 状态认为文件导入成功；必须检查 `state`。

`PUT` 创建体为 `{name,agent,account_id,git_connection_id,source,directory}`；Git 连接省略沿用用户默认，空串不绑定。空 `source` 规范化为 `empty`，空目录规范化为 `project`。服务端返回同一个空间，默认模型在首次接收时保存。

创建收据视图增补 `container_resources:{cpus,memory_mb,pids_limit}`，与 `/api/onboarding` 使用相同的公开字段投影。它反映读取时的新容器配置，不写入收据或变更资源配置的生效规则；网络、挂载、凭证等管理字段不在其中。

旧 `POST /api/sessions` 仍保留原行为，也可显式携带 `request_id` 使用新服务端收据；新版网页只用独立 PUT 路径并先发现 v1，避免旧服务端忽略未知字段后重复创建。不支持新协议时明确要求更新，不自动回退不具备恢复保证的 POST。

验证覆盖并发/重放、删除与放弃后的迟到请求、用户重建隔离、Git 撤权事务、schema 10→11 数据保留、上传路径/归档/总大小拒绝、原文件编辑后重放、Git 认证失败重试、进程重启的未知状态，以及三语网页确认丢失/刷新/核对流程。Git smart HTTP 用合成仓库和测试执行器；不将其描述为新一轮完整生产网络验收。
