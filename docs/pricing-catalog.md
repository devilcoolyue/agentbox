# 价格目录维护

[使用记录与额度](usage-and-quotas.md) · [文档目录](README.md)

价格目录与服务端版本独立发布。服务器获取目录后只生成候选，管理员在「系统设置 → 价目表」核对差异、勾选模型并确认应用。检查、编辑来源和自动检查都不会直接调整扣费。

## 部署实例如何使用

1. 将经过核验的 JSON 发布到可信的 HTTPS 地址，在价目表页面填写「远程目录地址」并保存。
2. 点击「检查更新」，查看新模型、每项单价的旧值/新值/涨跌幅、长上下文阈值、来源链接和核验时间。
3. 勾选要应用的模型并确认。新模型和已有跟随模型的调价默认勾选；自定义行默认不勾选，勾选意味着替换价格并恢复跟随。
4. 可开启「每天自动检查」。服务启动后检查到期状态，之后每分钟检查是否到期；成功或失败的尝试距今满 24 小时才自动重试。手动检查间隔至少 1 分钟。界面重新读取时显示候选，不在浏览器后台轮询。

未配置远程地址时不联网，仍可手动维护价格或核对内置旧快照。项目尚未随此功能发布公共价格目录服务，**不能把占位地址当作可用源**。内置 `legacy-2026-08-11` 只是从旧前端迁移的数据，未重新核验，不承诺最新官方单价。远程目录必须为每条模型提供有效核验时间；时间只表示目录维护者的声明，使用者应选择可信发布源。

已有价目表升级后全部按自定义处理，不会猜测哪些价格曾被管理员修改。手动改价格后，该模型自动变为自定义；也可以不改数字、直接点「设为自定义」。目录删除模型时只提示，保留生效价格。Agent 兜底行 `claude` / `codex` 由管理员单独维护，目录不能覆盖。

「需要核对的模型价格」检查系统默认模型、现有工作空间和最近 30 天用过的模型。区分无价和命中 Agent 兜底价，最近使用模型最多检查 200 种，超出显示截断提示。提示代表当前查价状态，不会重新定价历史记录。

## 调价、历史与回退

- 网页对话和自动起标题在调用 CLI 前锁定整张价格表，包含子模型的价格；回合中途调价不影响本回合。
- 每条新用量继续保存实际单价快照，并记录价格修订、目录版本、来源及核验时间。provider 自报的费用优先保留，表价拆分仍仅供参考。
- 终端异步补记在首次入账时锁定价格；同一行续写继续用首次快照。终端价格并非按终端进程启动时锁定，终端仍只记账不扣余额。
- 每次实际修改价目表保存修改前的表与跟随状态，最近 10 个版本持久化在配置中。恢复会先备份当前表，只影响之后开始的网页回合和首次入账的终端行，不改历史账单，也不回退目录地址。
- 应用、编辑和恢复都校验价格修订；另一管理员已修改时返回 409，需重新读取后核对。旧 `PUT /api/settings` 的整表编辑仍兼容，会保护未修改行的跟随信息、将修改行设为自定义并保留历史，但旧接口不提供并发修订检查。
- 获取、校验或缓存失败保留上一份候选与已生效价格；候选缓存位于 `cache_dir/pricing-catalog.json`，删除它不改变扣费配置。改来源后不会误用上一个来源的缓存。

## 目录格式

下面全部是**合成示例**，不是实际模型价格。金额单位为美元 / 百万 token；四项单价必须显式提供，只有确实免费或不适用才写 0，不得把未知价格填成 0。

```json
{
  "schema": 1,
  "version": "2026-09-26.1",
  "published_at": "2026-09-26T08:00:00Z",
  "entries": {
    "example-model": {
      "price": {
        "input": 2,
        "output": 8,
        "cache_read": 0.2,
        "cache_write": 0,
        "long_context_over": 200000,
        "long": {
          "input": 4,
          "output": 16,
          "cache_read": 0.4,
          "cache_write": 0
        }
      },
      "source_url": "https://example.com/pricing",
      "verified_at": "2026-09-26T07:30:00Z",
      "notes": "合成示例；标准服务档位。超过阈值后整轮按 long 档计算。"
    }
  }
}
```

没有长上下文档时省略 `long` 和 `long_context_over`。最多 200 个具体模型、文件最多 1 MiB，拒绝未知字段和非 HTTPS 来源链接。每个模型独立配置阈值，不共用一个全局阈值。长档是整轮换价；如果官方改成当前 schema 无法表达的规则，先扩展计价实现和 schema，不要强行套入旧格式。

## 维护与发布流程

1. 按需或定期核对官方定价页面。网页变化检测、第三方数据或 AI 提取可用于发现变化，但发布前由维护者核验。
2. 核对模型准确 ID、输入/输出、缓存读取/写入时长、长上下文阈值及服务档位。按实际 CLI 使用规则填写；只覆盖 API 标准计价，不把订阅费、Batch、Priority 或中转折扣混入同一行。当前缓存写入只有一个桶，无法表达同一回合混用不同缓存时长。
3. 更新受版本控制的 JSON，保留旧模型，修改 `version`、`published_at` 和受影响模型的 `verified_at`，用 `notes` 写明口径。
4. 运行校验：

   ```bash
   go run scripts/check-pricing-catalog.go /path/to/reviewed-catalog.json
   ```

5. 审查数据差异后，发布不可变版本文件和一个稳定入口（如 `catalog.json`）。稳定入口原子切换到新版本；保留旧版本便于追溯。只上传公开价格数据，不带配置或凭证。
6. 部署实例通过手动/每日检查发现变化，确认应用。发布 JSON 无需重编译 agentbox；修改内置兜底 JSON 才需要发布新二进制。

当前功能不抓取官方 HTML、不托管公共目录、不自动发布目录、不自动应用候选。未来若增加自动应用，应只针对明确跟随目录的模型，并继续保留版本与快照。
