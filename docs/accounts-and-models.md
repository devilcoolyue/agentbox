# 账号与模型

[返回文档目录](README.md) · [项目首页](../README.md)

## 接入方式

在「系统设置 → 账号池」新增账号，在同一弹窗选择账号类型、订阅 OAuth 或 API Key / 中转，并配置名称、使用范围及出口代理。环境变量位于「高级设置」。设置唯一 ID。ID 使用 2–32 位小写字母、数字、`-` 或 `_`，首位必须是字母或数字，创建后不修改。

| 类型 | 推荐的配置入口 | 保存位置 |
| --- | --- | --- |
| Claude 订阅 | 网页 OAuth 授权码流程 | 账号凭证目录的 `.credentials.json` |
| Claude API Key | 账号 `env.ANTHROPIC_API_KEY` | `config.json` |
| Claude 中转 / Bearer Key | 网页「中转站 API Key」 | 账号 env 中的 `ANTHROPIC_AUTH_TOKEN` 与可选地址 |
| Codex 订阅 | 网页 OAuth，粘贴完整回调地址 | 账号凭证目录的 `auth.json` |
| Codex API / 中转 | 网页填写 Key、地址、接口协议 | 账号凭证目录的 `auth.json` 和 `config.toml` |

网页创建账号时，凭证目录自动位于 `<data_dir>/creds/<id>/`。手工配置的账号可以使用 `accounts/<id>/` 或其他 `credentials_dir`；相对路径以 `config.json` 所在目录为基准。

普通用户可以选择授权范围内的账号创建空间，账号管理操作只对管理员开放。API 返回普通用户可见的账号概要时会隐藏环境密钥、地址和出口代理配置，但空间内的 CLI 运行需要实际凭证；这不是针对恶意终端用户的凭证托管隔离机制。

## 账号使用范围

管理员在「系统设置 → 账号池 → 使用范围」选择：

| 范围 | 普通用户 | 管理员 |
| --- | --- | --- |
| 全体用户 | 全部可用 | 可用 |
| 指定用户 | 仅列出的用户名可用；空列表无人可用 | 可用 |
| 仅管理员 | 不可用 | 可用 |

旧配置省略 `access` 或设为 `null` 时保持共享；网页新建账号也默认共享。新账号可在创建表单中直接设置范围，在授权前生效。配置示例：

```json
"access": { "mode": "users", "users": ["alice", "bob"] }
```

其他模式为 `{"mode":"all"}`、`{"mode":"admin"}`。HTTP 创建或 PATCH 账号时可带同样的 `access` 对象；PATCH 省略该字段或传 `null` 保持原设置，恢复共享需显式提交 `{"mode":"all"}`。HTTP 校验用户名存在，配置文件加载只校验格式，以便备份恢复及预配置；修改文件后需重启生效。授权按用户名匹配，删除用户后重用同名会继承相应授权，应先清理名单。

普通用户的 `/api/accounts` 仅返回可用账号，隐藏授权名单、环境密钥和出口配置，空间计数仅含本人。创建空间、REST 启动、每轮聊天、自动起标题、终端和网页 Git 执行都校验账号权限；订阅额度查询也受此限制。管理员拥有账号管理权限，但空间文件和历史仍只允许属主访问。

撤权后，原空间的文件、历史、停止和删除入口继续可用。后台凭证同步停止与被撤权空间双向交换；已连接聊天在下一条消息时拒绝，终端在下一次输入或最多一个心跳周期（30 秒）后关闭，使用私有关闭码 4004，前端停止自动重连。

授权是新操作的准入检查，不是上游令牌吊销。与授权更新并发、已通过检查的操作可能完成；已运行的 CLI、tmux 和已建立的代理连接也可能继续使用之前拿到的凭证。系统不会自动清空 home、杀容器或轮换上游令牌。如需彻底撤销，管理员需停止相关容器，并在上游轮换凭证；不能继续信任旧副本。此模式面向个人和可信团队，不适合向不可信终端用户隐藏共享密钥。

**回退限制：** 旧二进制不识别 `access`，回退会恢复全体共享，旧版保存配置还会丢失此字段。使用受限账号后，不能直接以旧版本继续开放服务；需先停用普通用户访问、验证配置备份并评估授权影响。运行目录、SQLite 和容器挂载不因本阶段变更。

## Claude 订阅授权

1. 新增 Claude 账号，选择「订阅 OAuth」；已有账号点击「管理认证」。
2. 点击「生成授权链接」，在浏览器打开链接并登录目标订阅账号。
3. 将授权页给出的完整授权码粘贴回控制台，完成登录。
4. 创建使用这个账号的空间，发送一条短消息验证。

授权链接对应一次独立授权流程，15 分钟内有效；超时或 state 不匹配时重新生成。服务端会同步并在需要时刷新 Claude OAuth 凭证，再立即分发给仍有授权且已经播种凭证的空间；新登录保存也会立即更新这些副本。日常同步、续期与池文件保存共用账号锁，避免服务端自己并发使用同一刷新链。若刷新链已失效，应重新授权。

也可导入已登录环境中的 `.claude/.credentials.json`，但该文件必须来自 CLI 使用文件保存凭证的环境。不要假定每种系统的凭证存储位置都相同；网页独立授权通常更方便，也能减少与本机 CLI 争用同一刷新令牌的情况。

## Codex 订阅授权

1. 新增账号时选择 Codex CLI 和「订阅 OAuth」，填写名称、ID、使用范围和出口代理。
2. 点击「保存账号并生成授权链接」，打开链接并用目标 ChatGPT 账号完成授权。
3. 浏览器跳转到 `http://localhost:1455/auth/callback?...` 后，复制地址栏里的**完整地址**并粘贴回控制台，再点击「完成登录」。本地没有回调服务时页面无法打开是正常现象，不必在服务器开 1455 端口。

授权采用 PKCE S256，回调必须带匹配的 state，链接有效期为 15 分钟。换令牌请求通过该账号的出口代理。生成链接时已保存账号；授权失败可在原弹窗重试，关闭后也可从账号列表继续认证，不会重复创建账号。

成功后写入 Codex CLI 的 `auth.json`（ID / access / refresh token、account ID、last_refresh），并将账号及已播种且仍有授权的空间切换到官方 provider，清除账号 env 中的 OpenAI Key / Base URL 覆盖。模型、推理强度和 MCP 设置保留。Codex CLI 负责后续刷新，服务端同步轮换后的凭证；运行中的 CLI 不会追溯更新，请重新打开终端或发起新的网页回合。

API Key 创建也在这个弹窗完成。保存失败会保留账号和输入以便重试；仅打开表单后关闭不会创建账号。新建 Key 账号成功后，可从「管理认证」测试连接。

## 手工配置账号

下面是 `accounts` 数组中的条目示例，合并到现有配置时按需选择。占位密钥不能用于实际调用：

```json
{
  "accounts": [
    {
      "id": "claude-sub",
      "type": "claude",
      "label": "Claude 订阅",
      "credentials_dir": "accounts/claude-sub"
    },
    {
      "id": "claude-api",
      "type": "claude",
      "label": "Claude API",
      "env": { "ANTHROPIC_API_KEY": "REPLACE_WITH_YOUR_API_KEY" }
    },
    {
      "id": "codex-sub",
      "type": "codex",
      "label": "Codex 订阅",
      "credentials_dir": "accounts/codex-sub"
    }
  ]
}
```

凭证目录内容：

```text
accounts/
  claude-sub/
    .credentials.json
  codex-sub/
    auth.json
    config.toml          # 有自定义 provider、MCP 等配置时同时准备
```

也可在可登录的环境完成 `codex login`，再把该环境实际使用的 `~/.codex/auth.json` 放入对应目录。网页授权生成独立的凭证，避免与本机共用刷新链。

## 中转与 API Key

网页登录配置中可以填写 Key 与 Base URL，再用连通性探测检查结果。

- Claude 网页 Key 入口使用 Bearer 令牌 `ANTHROPIC_AUTH_TOKEN`；如果供应商要求原生 `ANTHROPIC_API_KEY`，按上面的 env 示例配置。
- Claude 切回订阅时，使用「清除中转站配置，切回订阅凭证」，并确认有效 OAuth 凭证已存在。
- Codex 可以选择 `responses` 或 `chat` 接口协议。应匹配实际 provider 和已安装 CLI 支持的协议，保存成功不代表上游一定兼容。
- Codex 的 Base URL 留空会切回官方 provider；填写地址时选用 agentbox 管理的中转 provider，并更新当前 profile。模型、推理强度、MCP 等其他配置保留；TOML 重写不保留注释与原排版。

账号 env 随每次 CLI 执行注入，新网页回合能取得最新值。已运行进程不会追溯更新；终端应重连后新建 tmux 窗口。账号出口代理的绑定和验证见[网络配置](networking.md)。

## 账号可用模型

每个账号可以有自己的模型列表，例如 DeepSeek 中转账号只列 DeepSeek 模型，不再显示 GPT 模型。在「系统设置 → 账号池」点账号行上的「沿用系统模型列表 / N 个可用模型」，或 ⋯ 菜单「可用模型…」打开。新账号认证成功后会自动打开并读取一次。

「从上游读取」按账号的接入方式查询，请求走账号绑定的出口代理，读取本身不保存任何内容：

| 账号 | 读取来源 | 思考强度 |
| --- | --- | --- |
| Claude API Key、中转 | `{Base URL}/v1/models`（或 `/models`），兼容 Anthropic 分页 | 读 Anthropic 的 `capabilities`：`effort` 支持时用它列出的档位，否则 `thinking` 接受 `enabled` 时用思考预算，`thinking` 不支持时标为不支持调整；中转站没带这个字段时按官方模型目录补全 |
| Claude 订阅 | `api.anthropic.com/v1/models`，使用订阅令牌，过期时先续期 | 同上，官方接口会带回每个模型的档位 |
| Codex API Key、中转 | `{Base URL}/v1/models`（或 `/models`） | OpenAI 风格的列表不含能力信息，按官方模型目录补全 |
| Codex 订阅 | Codex CLI 自己使用的 ChatGPT 模型目录，按镜像里的 CLI 版本过滤 | 带回每个模型支持的档位 |

两个订阅来源都不是公开文档化的接口，上游调整后可能读取失败；失败时可以用「官方目录」或手动添加模型 ID。Codex 订阅只用账号池里的访问令牌，不自己续期（续期由 Codex CLI 负责）；令牌过期时在使用该账号的空间里发一轮对话，或重新授权后再读。含 `/` 等字符、CLI 不能安全接收的模型 ID 会单独列出，不进入候选。

第一次读取默认全选，可以取消不需要的模型；筛选框配合「全选」只作用于筛选出的行。每行可以单独设置思考强度、选一个默认模型；「批量设置强度」把同一套设置应用到筛选后仍可见的已勾选行，适合中转账号一次配好同一家族的模型。读取结果里的思考强度按 **这个账号已有的设置 → 上游报告 → 「模型管理」里同一模型（含去掉 `-YYYYMMDD` 日期后缀的同名模型）→ 官方模型目录** 的顺序取，管理员明确设过的不会被上游或官方目录覆盖。再次读取不会改动已保存的选择：新出现的模型标「新」且不勾选，上游不再列出的已保存模型标「上游未列出」；已保存但强度未设置的模型会补上这次读到的档位。

### 官方模型目录

中转站和 API Key 账号拿不到订阅账号那样的能力信息：OpenAI 风格的 `/v1/models` 只有模型 ID，很多中转站不转发 Anthropic 的 `capabilities`，有的干脆没有模型列表接口。官方并没有不需要账号就能查的模型能力接口，但 Agent 镜像里的两个 CLI 都自带模型目录，不登录也能读出来：

- **Codex CLI**：`codex app-server` 的 `model/list`，返回 CLI 内置的模型目录及每个模型支持的推理档位。
- **Claude Code**：stream-json 模式的 `initialize` 控制请求，返回 CLI 模型菜单里的模型及支持的 effort 档位。

服务端在一次性的隔离容器里读取（与镜像更新的候选验证同一套隔离：`network=none`、只读根、UID 1000、不挂载任何目录、不传账号凭证和镜像 ENV），结果按镜像 ID 缓存，换镜像后重新读；读取失败或只读到一部分时 5 分钟后重试。CLI 目录只列当前模型，较早的模型（如 Claude Opus 4.x、Sonnet 4.5、GPT-5.4）由随服务端发布的**内置快照**补齐，快照来自 Anthropic Models API 的 `capabilities` 与 Codex CLI 内置目录，注明核对日期；没有 Docker 或读不到镜像时只用快照，原因只记服务端日志。

官方目录用在两处：

- 「从上游读取」后，前面几层都没有给出思考强度的模型，按模型 ID 在官方目录里查（同一模型的 `-YYYYMMDD` 日期后缀、Claude Code 的 `[1m]` 标记视为相同，改了名字的中转模型不会匹配），来源显示「由官方模型目录提供」；没有显示名称的模型也顺带补上名称。API Key、中转账号读不到模型列表时，不再只报错，而是改为列出官方目录，并在上方写明上游返回的错误。订阅账号读取失败仍按错误处理（多半是登录问题）。
- 弹窗里的「官方目录」按钮：不访问上游、不需要订阅登录，直接列出官方模型，标「官方目录」。账号还没有模型时预先勾选 CLI 当前菜单里的模型，较早的模型不勾选；已有列表时都不勾选，只给已有但缺少强度的模型补上档位。

官方目录只是建议，**保存后才生效**：对话时服务端只认账号里保存的能力，不会因为模型 ID 与官方相同就自动替中转账号打开强度选项。中转站不转发 `effort` / `reasoning` 参数时，可以把该模型改成「未知」或「不支持调整」。

保存后：

- 使用这个账号的工作空间，对话模型下拉只显示勾选的模型，没有「自定义模型」；服务端也拒绝列表外的模型（`chat_options_invalid`）。
- 思考强度跟模型走：只有明确支持调整的模型才显示强度选项，并且只列该模型的档位，默认选中一个具体档位（规则见下文「网页选择规则」）；其他模型不显示强度，使用模型默认值。Claude 面板里模型较多时，强度行固定在面板底部。
- 新建空间使用账号的默认模型。已有空间保存的模型不在列表里时，网页对话、终端启动和 `ANTHROPIC_MODEL` 都改用账号默认模型；空间保存的值不改，列表以后再包含它时恢复使用。切换到有模型列表的账号时，空间模型直接改成新账号支持的值。
- 浏览器记住的模型已不在列表里时，网页切回账号默认模型并提示。

### 在对话中显示

「系统设置 → 模型管理」分「账号模型」「价格」「系统模型列表」三个标签页。「账号模型」按接入协议分成「Claude 协议」（Claude Code 账号）和「OpenAI 协议」（Codex 账号，含 DeepSeek 等中转）两组，每个账号一张卡片，默认收起，只显示显示数量、默认模型和待核对的价格数；点卡片展开它的模型（只有一个账号有模型列表时直接展开），「全部展开」一次打开所有卡片，筛选时只展开有匹配的卡片。说明文字收在各标签页的「?」里。展开后每行一个显示开关，切换后立即保存。关闭只是不出现在对话页的模型下拉里：模型仍属于账号，随时可以重新打开；正在使用它的空间、浏览器记住的选择和服务端校验都照常（当前选中的隐藏模型仍显示在下拉里，免得选中项凭空消失）。默认模型始终显示，开关不可关闭，要隐藏它先在「可用模型」里换默认模型；至少要保留一个显示的模型。没有配置可用模型的账号沿用系统模型列表，卡片里只提供「配置可用模型…」入口。

每行还显示这个模型实际计费的单价（输入 / 输出，美元每百万 token），按价目表的查找顺序得出：精确模型 ID → 去掉日期后缀 → agent 兜底价。用的是 `claude` / `codex` 兜底价或根本没有价格时标成警示色——中转站的模型（DeepSeek 等）没有单独配价时就会落到兜底价上。点价格可以直接给这个模型设四档单价（写进同一张全局价目表，存为自定义价格）；价格目录里有这个模型时也可以选「跟随目录价格」。价格按模型计，与账号无关，长上下文档位和目录同步在「价格」标签页（原「价目表」，见[用量与额度](usage-and-quotas.md)）。

「系统模型列表」标签页是新空间默认模型、候选模型及其能力，只对没有配置可用模型的账号生效，页内写明有哪些账号在用；所有账号都配置了可用模型时提示目前不影响对话。读取上游模型时，上游没有报告思考强度的模型仍会参考这里同名模型的配置。

隐藏标记保存为模型条目的 `"hidden": true`，「可用模型」弹窗保存时原样保留，并给这些行标「已隐藏」、不能设为默认。只有账号的 `models` 支持这个字段，全局 `models` 里出现会被配置校验拒绝。账号 PATCH 只改 `models` 时，原默认模型被隐藏或移除就改用第一个显示的模型。

取消全部勾选再保存，会恢复使用系统模型列表。限制只作用于网页对话和服务端写入的 CLI 默认模型；终端里手动用 `/model` 或命令行参数切换的模型不受约束。

配置文件中对应账号条目的 `models`（与模型管理相同的 `{id, label, reasoning}` 结构）和 `default_model`：

```json
{
  "id": "deepseek-relay",
  "type": "codex",
  "models": [
    { "id": "deepseek-v4", "label": "DeepSeek V4", "reasoning": { "support": "supported", "control": "effort", "levels": ["low", "high"] } },
    { "id": "deepseek-v4-flash", "label": "DeepSeek V4 Flash" }
  ],
  "default_model": "deepseek-v4"
}
```

`models` 缺省或为空表示沿用系统模型列表；非空时 `default_model` 省略则取第一个，必须在列表中，最多 500 个。账号 PATCH 的 `models` 整表替换，`[]` 恢复系统列表；只改 `models` 时原默认模型仍在新列表中就保留，否则改为第一个。网页保存列表时会把旧的账号级能力覆盖（`model_reasoning`）合并进各模型并清空，避免同一模型两处配置。旧二进制不认识这两个字段，回退后会显示全部系统模型，且再次保存配置会丢掉它们。

## 默认模型与候选列表

在「系统设置 → 模型管理 → 系统模型列表」维护 Claude / Codex 的模型 ID 与显示名称，并选择「新空间默认模型」。这份系统列表供**没有配置可用模型的账号**使用。当前初始值：

| Agent | 初始默认模型 |
| --- | --- |
| Claude | `claude-opus-5` |
| Codex | `gpt-5.5` |

模型名称来自当前仓库默认配置，不是动态查询上游能力的结果。使用其他 provider 时应改成它实际支持的模型 ID，并同步核对[价目表](usage-and-quotas.md)。

默认模型必须存在于对应候选列表中。更换系统默认值只影响随后创建的空间；旧版尚未保存模型的空间，会在新版首次初始化时补齐当时的默认值。

空间启动时将保存的默认模型写入 CLI 配置，Codex 同时处理启用的 profile，保留 provider、推理强度和 MCP。对话输入框单独选模型只作用于网页对话，不修改这个空间的终端默认值。

## 推理强度与思考预算

「系统设置 → 模型管理 → 系统模型列表」每个模型旁可编辑能力：自动识别、支持情况未知、支持调整、不支持调整。支持调整时选择调整方式与允许档位；账号池每行的「模型能力」可按模型 ID 覆盖同一模型在该账号下的行为。账号覆盖选择「自动识别 / 跟随上级配置」会删除该条覆盖；显式「支持情况未知」会阻止低优先级自动识别。

优先级是 **账号覆盖 → 账号可用模型 → 模型配置 → CLI 元数据 → 未知**，模型 ID 精确匹配，不根据名称猜测模型家族能力。`GET /api/sessions/{id}/models` 仅允许空间属主且仍有账号授权的用户调用；响应只含模型和生效能力，不含账号环境变量、provider 地址或凭证。停止的空间不会为此启动；运行的 Codex 空间通过 `config/read`、`model/list` 查询目录，最多等 5 秒，不创建线程或发起推理。自定义 provider、OpenAI 地址被覆盖或查询失败时回到未知，不将官方目录当作中转模型能力证明。Claude 当前没有接入可验证的模型目录，需管理员按实际服务配置。

模型条目可选字段示例（示例 ID 不代表真实模型）：

```json
{
  "id": "example-model",
  "label": "示例模型",
  "reasoning": {
    "support": "supported",
    "control": "effort",
    "levels": ["low", "medium", "high"]
  }
}
```

账号条目可配置 `"model_reasoning": {"example-model": {"support": "unsupported"}}`。账号 PATCH 的 `model_reasoning` 整表替换，`{}` 清除覆盖，省略或 `null` 保持不变。所有字段随配置原子保存；旧配置缺省兼容为未知，无数据库迁移。旧版本写回配置可能丢掉新增能力字段，回退前应保留配置备份。

| 调整方式 | 传递方式 | 注意事项 |
| --- | --- | --- |
| Codex 推理强度 | app-server `turn/start.effort`；exec `-c model_reasoning_effort="…"` | 只显示该模型允许的档位；查询不到时需手动展开指定 |
| Claude 原生推理强度 | `claude --effort …` | 执行前检查容器 CLI 是否提供此选项；清除本次进程继承的预算与 effort 环境变量，不改账号文件 |
| Claude 思考预算（旧模式） | `MAX_THINKING_TOKENS`，并设置 `CLAUDE_CODE_DISABLE_ADAPTIVE_THINKING=1` | low / medium / high / xhigh 对应 4096 / 13000 / 24000 / 31999；只适用于支持固定预算的模型和 CLI，不能把预算当成原生 effort |

新 Claude 模型应优先配置原生 effort。旧模式不会主动传 `--effort`，但 CLI 仍可能根据模型自动产生 effort；自适应模型也不一定接受固定预算。管理员需按实际上游验证，不能仅凭菜单选择就认定预算生效。CLI 或组织设置可能限制最终档位。

网页选择规则：

- 已知支持的模型只列允许的档位，没有「默认强度」项：用户没选时用一个具体档位并照实发送，下拉和输入框旁显示的就是本轮实际使用的档位。默认档位依次取账号 CLI 配置里的默认强度（Codex `config.toml` 的 `model_reasoning_effort`，含当前 profile；Claude 账号环境变量 `CLAUDE_CODE_EFFORT_LEVEL`）、Claude 的 `high` / Codex 的 `medium`（两家 API 不指定时的默认值），都不在档位里时取居中一档。档位名称按 API 取值显示英文（Low / Medium / High / Extra High / Max 等）。
- 未知模型仍保留「默认强度」，表示本轮不覆盖，可继承 CLI 配置、profile 或恢复线程设置，**不等于关闭推理**；展开「手动指定」后才允许尝试具体档位。档位可能被上游拒绝，应用不自动降档重试。配置了可用模型的账号不提供「手动指定」，未知与不支持的模型都不显示强度选项。
- 切换模型仅在新模型明确支持同档位、且调整方式相同时保留选择，否则改用新模型的默认档位并提示。升级时保留旧浏览器记录中的模型 ID，旧强度清空；新记录保存调整方式，避免预算被解释为原生 effort。
- 服务端在执行前重新校验；显式不合法的选择直接报错，消息可恢复默认后由用户点击重试，这一轮不带强度。`turn/start` 被拒绝或提交后断线不会再次走 exec 重放。
- **明确不支持与未知不同。** 明确不支持时禁止显式档位，并检查 home / workspace CLI 配置和启用的 profile。Codex 恢复线程仍带强度时拒绝提交；无法检查继承状态的 exec 回退也拒绝。当前 Claude CLI 对自定义模型仍可能自动加入 thinking / effort，没有验证过可安全省略它们的通用参数，因此明确不支持时返回兼容性错误。需要换用兼容模型的 CLI / 中转配置并验证，不能用隐藏选项来假装底层已关闭推理。

以上限制仅管理网页对话；不会改写终端或共享账号的强度配置。未知模型的尝试仍可能收到 CLI / 上游兼容性错误。

## 切换空间账号

空间的 ⋯ 菜单「切换账号」可改用同类型（Claude / Codex）的另一个账号，接口为 `PUT /api/sessions/{id}/account`（`{"account_id": "…"}`）。只列出、也只接受空间属主有权使用的账号；Agent 类型不能切换。

切换按以下顺序执行，全程持有空间锁：

1. 停止容器。终端、远程浏览器和后台命令随之结束——它们内存里还拿着旧账号的登录，留着会在交接后把续出的新令牌写回 home。
2. 按日常凭证同步，把空间里续出的较新令牌收回旧账号池（刷新令牌是轮换制，不收回的话旧账号池那份已作废）。旧账号已对该用户撤权时跳过收回。
3. 删除 home 里的登录文件：Claude 的 `.claude/.credentials.json` 与 `.claude.json` 里缓存的账号信息，Codex 的 `.codex/auth.json` 与 `config.toml` 里的连接配置。
4. 改绑账号。下次启动由新账号池重新播种凭证；新账号的同步与播发不会采纳 home 里的旧凭证。

文件、home 里的其他配置（模型、MCP、技能）、对话历史和续聊用的 provider 会话 ID 都保留；如果续聊在新账号下报错，新建对话线程即可。之前在运行的空间，网页会在切换后重新启动它。正在执行的对话回合、待核对的消息或未结束的项目导入会让切换被拒绝（`chat_busy` / `chat_pending` / `import_pending`），等它们结束后再切换。已经入账的用量仍记在原账号名下；终端补记按扫描时空间绑定的账号归属，切换前刚结束、尚未扫描到的终端回合可能记到新账号。

## 凭证同步与账号删除

空间启动时从账号池播种凭证，运行期间也会收敛 CLI 更新后的凭证。不要在服务运行中反复覆盖账号文件来“固定”旧令牌，旧刷新令牌可能已经作废。

一个账号仍被任何空间引用时不能删除，包括已经停止的空间。先处理这些空间，再删除账号条目。删除账号默认保留其凭证目录，管理员可在确认不再需要后自行归档。

系统备份会覆盖**每个账号实际的 `credentials_dir`**、网页创建的 `<data_dir>/creds/` 与旧版 `accounts/`。恢复时将账号路径指向恢复目录内的独立凭证副本；OAuth 刷新令牌可能已轮换失效，需要逐账号验证，详见[备份与恢复](../deploy/README.md#备份与恢复)。
