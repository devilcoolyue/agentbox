# 聊天草稿与恢复

[使用指南](user-guide.md) · [M3 记录](milestones/m3.md)

当前开发源码已接入**未发送草稿和待确认消息**的隔离与恢复，尚未发布。网页发现新消息协议后使用持久接收、按原 ID 查询和显式核对；旧服务端保留旧发送路径并提示限制。当前证据包括本地存储、服务端合成执行和真实浏览器合成 API，完整联合故障与真实设备验收仍在 M3-05。

## 草稿保存

输入框底部的草稿图标打开保存设置，提供共享开关、清除和附件复查，覆盖草稿与待确认副本。正常保存说明收在弹层中；恢复、保存失败、禁用保存和附件问题仍在输入区提示。默认在此浏览器保存正文 7 天，只保存文字、选项、原始文件名和附件引用，不保存附件文件内容、账号凭证或登录 token。

- 隔离范围为浏览器站点、实例身份、用户创建身份、空间、对话。删除重建同名用户、恢复到一个新实例，不自动继承旧浏览器草稿。
- 同一身份的每个页面有独立写入编号；每标签页只在会话存储中保存恢复指针。多个页面编辑同一对话时分别保留，迟到的存储事件不覆盖当前输入；刷新按本页指针恢复。新页面尚无指针时可读取该对话最近的草稿，编辑后另存一份。
- 7 天从记录的最近一次保存计。过期副本在下次读取/保存时清理，浏览器关闭时没有后台定时删除进程。大小和记录数有上限，存储失败保留本页输入并明确提示，不静默驱逐其他草稿。
- 关闭保存会清除当前身份在本浏览器的持久副本；本页输入和页面内的空间切换草稿仍可使用，刷新后不恢复。重新启用仅保存当前页面已持有的内容。
- 退出、令牌失效或另一页面改变登录身份，会清理旧身份的副本和界面。刷新/关闭页面则先保存，区别于退出登录。不要把本机草稿当作备份；浏览器清理站点数据也会删除它们。

持久清理由发起退出/登录替换的页面执行；其他页面收到令牌变化只清自己的内存与界面，不重复删除当前登录的新副本。浏览器只额外保存不含令牌/正文的身份范围提示，用于新登录初始化前清理上一身份。这样被冻结的旧页面稍后恢复时，不会删除同一用户重新登录后写下的内容或新令牌。

服务端未提供身份范围或稳定对话编号时，不启用持久保存。旧服务端仅保留当前页面内能够识别归属的内容；未知空对话发生线程切换后不能复用上一条的内容。完整恢复需当前开发版前后端配套。

## 待确认消息

点击发送时，网页在异步附件检查前冻结文字、模型和推理选项。检查期间输入、附件或选项变化，会要求重新点击发送。默认开启本机保存时，待确认副本成功写入后才提交服务器并移出输入框；本机存储拒绝或超限则保留输入、停止提交。接收等待期间可以编辑下一条草稿，不覆盖冻结副本。

- 状态区默认只占一行，优先显示待确认或待核对的消息，其次显示当前任务；右侧查询图标只查询，不展开详情。点击状态栏展开记录，多条记录显示数量并在限定高度内滚动；单条记录展开后可直接操作，多条记录按需展开原文、冻结的模型/推理设置和附件名称。Escape 收起详情并返回状态栏。正文相同的 WS 广播不会清除副本，乱序旧修订不会覆盖新状态。
- 刷新、多页面、恢复联网或重新连接只查询结果。确认丢失时先点「查询结果」；「重试原消息」也会先查询，仅在未查到接收记录时用原 ID 和原内容提交。不会自动换 ID 重发。
- 待核对状态阻止新回合。先查看对话历史和文件，再点「已检查结果，继续」；这只允许后续新工作，不重跑旧任务，也不保证已经脱离连接的进程停止。
- 尚未接收的内容可显式放弃；服务端围住原编号后，迟到请求也不能再执行。放弃不是取消已经接收的任务。明确失败、中断、核对或放弃后可以复制回空输入框，不覆盖现有草稿、不自动发送；跨对话复制额外确认。复制后按当前选择的模型/推理设置编辑并发送。
- 待确认正文自首次冻结起保存 7 天；过期读取会删除本机正文/附件副本，但保留少量查询标识，直到明确处理该记录。没有后台浏览器过期进程。单份 JSON 上限 400,000 字符，当前身份持久区合计 2,000,000 字符、500 条；容量不足不静默驱逐其他消息。
- 关闭保存会清除持久副本，但本页待确认内容仍可处理。刷新后可以查询服务器已接收的活动任务；**服务器尚未接收的内容及编号可能无法找回**，不能把暂时没有活动回执当作旧请求永远不会到达。重新启用只保存本页仍持有的副本。
- 退出清理当前身份的本机副本与确认框，不取消服务器已经接收的任务，也不删除服务端历史/回执。浏览器清理站点数据同样不等于服务端放弃请求。

## 对话与附件

新网页在历史请求中显式使用 `draft_context=1`，让空对话也取得稳定编号。服务端只保存一个不含正文的 `draft_context` 元数据事件，使尚未发消息的对话仍能从历史列表返回；重复新建空对话复用当前空对话，不堆积重复空项。元数据不是用户消息、不调用模型、不计用量；旧渲染器忽略这个事件。

恢复附件时先检查当前用户共享目录中引用的普通文件，再展示可用状态。不存在、链接、目录、未完成的上传或无法验证的引用会保持待处理，不能直接发送。可以重新检查，或移除后重新上传；不要只在提示词里留下一个看似有效的旧路径。

发送前再次检查附件，检查期间输入、附件或选项变化则要求重新点击发送；不会把后来编辑的内容悄悄自动发出。切换空间/线程或退出会取消旧上传与校验，迟到结果不能改变新空间的输入框或投递提示。仅从服务端回执恢复时也会重建附件引用并复查，不退化成未经检查的裸路径。附件仍沿用 48 小时清理，但历史和已接收回执引用会保留；浏览器未发送草稿不会延长服务器文件寿命。

## 接口范围

- `/api/me` 增补 `draft_protocol:1`、`draft_scope`。范围来自稳定实例身份与用户创建身份的摘要；实例身份不可读时范围为空，登录仍可用，持久恢复停用。
- `GET /api/sessions/{id}/history?draft_context=1` 返回 `active_thread`，必要时分配并登记空对话；原历史入口和旧客户端继续可用。
- `POST /api/sessions/{id}/attachments/validate` 接收 `{paths:[...]}`，最多 64 个 `/shared/.images/` 或 `/shared/.file/` 下的叶子文件，返回同顺序 `{valid:[boolean,...]}`。只校验属主范围内的引用，不返回文件内容或宿主路径，不启动容器。

`draft_protocol` 只表示草稿上下文与附件检查能力，**不是持久消息接收协议**。网页使用独立的 `chat_protocol:1` / `chat_scope` 选择新路径；已选择新协议后，网络或格式错误不会触发无 ID 的旧 WS 降级。

## 开发中的持久回执

服务端接口、请求 ID、状态和恢复规则见[聊天协议 v1](chat-protocol.md)。

当前源码的 schema 12 回执已接入独立 HTTP API、原回合执行器及网页发送。回执冻结提示词、模型、推理选项、附件引用、线程和实例范围，保存独立请求 ID、稳定回合 ID 与修订号。同一 ID 的重放只读取原回执；改变内容冲突，不另开回合。启动恢复将未结束的 accepted/starting/running 改为 uncertain；核对后的 reviewed 保留原原因，也不会重跑旧 ID。明确放弃尚未到达的 ID 会留下围栏。

系统备份包含数据库回执中的提示词及引用，不含附件文件；完整文件恢复仍需 full 备份。删除空间/用户时清空回执正文并保留重放围栏，不会擦除已有备份。服务端在用量收尾与转录同步后保存最终回执；缺少 provider 结束事件、输出流损坏、历史或用量写入失败均保持待核对。用户确认中断与服务关闭分别处理。该协议不追溯补齐旧 WS 的接收保证，也不证明模型产出的任务质量或未上报的上游费用。
