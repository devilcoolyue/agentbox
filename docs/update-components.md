# 三类更新与生效范围

[使用指南](user-guide.md) · [兼容矩阵](compatibility.md) · [升级与回退](releases.md)

v0.1.11 在管理员「系统设置 → 关于与更新」中提供三类更新的版本观察与入口。网页原「客户端更新」改名为「Agent 镜像更新」，避免和本机桌面应用混淆。网页界面随服务端发布；桌面说明需要后续独立桌面包才会出现在已安装应用中。

| 对象 | 版本与兼容依据 | 生效方式 |
| --- | --- | --- |
| 服务端 | 正在运行的构建版本、服务端 schema；发行版本比较不证明候选兼容，切换前由原升级流程核验配置与数据库 | 更新服务端及嵌入网页；服务重启会短暂断开连接，进行中的网页对话可能中断。刷新网页载入新界面，工作空间不必仅为服务端更新而重启 |
| Agent 镜像 | 当前配置镜像的 ID 和 Claude/Codex 版本标签；标签观察不证明 CLI 协议或真实模型调用可用，也不是所有运行中空间的版本 | 原更新器构建/验证/切换所选镜像；运行中空间继续使用原镜像，停止再启动后采用所选镜像。服务端和桌面应用不因此重启 |
| 桌面应用 | 网页不能读取本机安装版本；在桌面「设置 → 关于与更新」查看实际版本和本次登录声明的连接能力 | 在桌面应用内检查和确认安装；只重启本机应用，连接暂时断开，远端任务继续运行。开始前停止本机同步及文件传输，不升级服务端或镜像 |

服务端自动升级的备份是**系统备份，不含项目文件**。项目恢复需要完整备份；更高 schema 不能直接用旧二进制打开。详情见[数据库迁移与回退](architecture/database-migrations.md)。

镜像页面的「任务开始时 / 目标」描述最近任务的两端，不应读成当前所有容器的版本。即使 CLI 版本及浏览器组件验证通过，上游协议和真实调用仍需单独验收；v0.1.11 同时加入[候选行为验证](agent-image-validation.md)。资源限制也不能混为镜像重启规则：CPU/内存/进程上限在容器创建时读取，已有容器保留原值，单纯停止再启动同一个容器不会刷新其资源上限。

## 本地版本观察

「刷新本地版本信息」调用管理员只读接口 `GET /api/updates/components`，记录观察时间；最多等待 3 秒读取已配置 Docker 镜像的元数据。该接口不访问发行/npm 源、不拉取或构建镜像、不运行 CLI、不启停空间，也不提交升级任务。原有服务端更新检查和自动镜像策略继续独立执行。

- `labels_only`：已读到配置镜像，显示存在的版本标签；缺失标签显示未知，不伪造版本或兼容通过。
- `unavailable`：无法读取 Docker/配置镜像，版本与兼容性保持未知；宿主路径和 Docker 原始错误不发给网页。
- `changed`：读取期间所选镜像配置变化，丢弃旧镜像 ID/版本，刷新后再观察。
- 读取失败、超时或离开页面时，网页清空本次版本结果，迟到响应不能覆盖新页面/新登录。

这些是一次观察，后台切换镜像或升级后可重新刷新。桌面状态只显示服务端当前提供的协议和同步开关；网页不会把它解释为某台已安装客户端的实际连接或版本。

桌面应用中的兼容说明区分未连接、基础模式、协议 1 的项目/同步能力和未知协议。能力来自本次登录，仍需按候选发行说明核对版本组合；显示连接能力不代表更新候选已经在该服务器上验收。正式签名、公证、旧包升级和真实设备验收继续按 M5 单独推进。
