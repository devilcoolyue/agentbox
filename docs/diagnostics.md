# 分层环境诊断

[排障手册](troubleshooting.md) · [错误码与操作编号](errors.md) · [API](api.md)

当前源码新增分层检查；旧发布包可能尚未包含。检查不会调用模型、刷新 OAuth、启动容器、修改项目文件或修复配置。每项分别报告 `passed`（通过）、`failed`（失败）或 `not_checked`（未检查）。**HTTP 200 或 CLI 退出码 0 不表示模型可用，也不表示所有项目都检查过。**

## 网页入口

- 管理员：系统设置 → 容器与资源 →「环境检查」，查看实例级结果。写入探测仅在数据目录内创建独立临时目录，写入并同步一个小文件，再清理；Linux 上同时尝试将这个文件的属主设为 `1000:1000`，不更改任何现有文件属主。
- 所有用户：自己空间的「更多操作」→「环境检查」。只返回该空间的账号授权、额度、运行依赖和根目录权限检查；不返回实例用户列表、会话总数、磁盘容量数字或其他空间的信息。账号已撤权时，不读取其凭证配置。
- 两种窗口均可重新检查、查看处理建议、导出脱敏 JSON。关闭、退出登录或离开对应视图会取消后续请求/连接；未完成或失败的整次请求不能导出成成功报告。

空间检查不执行写入探测，只固定目录句柄并核对 `workspace` / `home` 根目录的类型、UID 与属主读写执行权限，不跟随符号链接，不递归读取项目文件。它不能证明全部子文件、ACL、安全模块或容器内运行时均可用。

原「导出诊断」按钮继续使用管理员 `GET /api/diagnostics`，保留版本、平台、schema、会话数量、磁盘水位、资源和用量同步的旧字段，并增加 `environment`。该只读导出不做临时写入探测，所以写入/属主项目显示“未检查”；要实际验证这两项，请主动打开环境检查窗口。

## 每项到底检查了什么

| 检查项 | 通过的含义 | 不代表什么 |
| --- | --- | --- |
| 配置（实例） | 当前内存配置通过现有 schema/取值校验 | 磁盘上被外部改动的配置已生效，或提供方账号有效 |
| Docker | daemon 的 Ping 接口可访问 | 容器能创建、CLI 能执行 |
| 指定镜像 | 配置中指定的镜像可被 ImageInspect 读取 | 镜像内 CLI、MCP 或模型调用正常 |
| 数据盘 | 可读取当前可用容量，且不为零、不低于配置的保留值 | 工作区有硬配额，或之后不会写满 |
| 服务端写入（主动实例检查） | 独立临时文件创建、同步、删除成功 | 全部用户文件都可写 |
| 容器属主（Linux 主动实例检查） | 在独立临时文件上设置 `1000:1000` 成功 | 所有历史文件属主均正确；非 Linux 不检查此项 |
| 空间目录（空间） | 固定根目录的元数据符合容器用户访问要求 | 所有项目文件或实际容器访问已验证 |
| 账号配置 | 支持的 API Key / OAuth 凭证配置存在且可读取 | Token 未过期、可成功续期、模型已授权或上游可达 |
| 账号授权（空间） | 属主当前获准使用绑定账号 | 已发给容器的旧凭证被撤回 |
| 额度（空间） | 当前余额规则允许开始回合 | 本轮最终费用已知 |
| WebSocket（浏览器） | 诊断通道完成握手，并收到匹配此次编号的固定响应 | 所有其他 WS 路径、长连接稳定性或 CLI 调用正常 |
| 模型调用 | 始终为“未检查” | 不会根据文件存在或其他绿色项目推断“模型可用” |

账号配置检查识别当前产品使用的 Claude OAuth / 中转 Key、Codex `auth.json` / OpenAI Key 等形式，只描述本地凭证存在状态。自定义认证或无需认证的私有提供方仍需按其配置人工核对，不能仅凭此项判断实际模型可用性。

Docker Ping 与镜像读取各有 3 秒超时，HTTP 检查上下文为 10 秒，浏览器 WS 探测为 5 秒；本地文件系统调用仍受实际挂载响应影响。没有远程模型或账号网络探测。数据目录不存在时报告失败，不自动初始化实例或创建数据库。

## WebSocket 与报告来源

服务端环境报告中的 WebSocket 一直是 `not_checked`：服务端不能替访问者验证其浏览器到反向代理的路径。网页另开一个有登录/同源校验的诊断连接，收到固定的诊断响应后，才在窗口里显示“通过”。连接不加入聊天房间，不接收提示词，也不产生用量。

导出文件保留原服务端 `checks`，另外记录带 `source:"browser"`、时间和独立操作编号的 `client_checks`；不会把浏览器观察改写成服务端事实。服务端 WS 日志中的 `sent=true` 只说明响应已交给连接，不证明浏览器已收到。请求在到达 Agentbox 前就失败时，服务端可能没有对应日志。

报告只含白名单字段及固定检查文案，不含账号/用户名、凭证、提示词、文件内容、宿主路径、原始 Docker 错误或原始配置。网页导出会再次筛掉未知字段和不属于空间范围的检查。操作编号用于日志关联，不是认证或任务幂等凭据。

## 命令行

```bash
# 原兼容行为：只校验配置，不连 Docker、不写文件、不打开/迁移数据库
agentbox check-config --config /实际配置/config.json

# 明确运行环境检查：访问 Docker，并执行独立临时写入/属主探测
agentbox check-config --config /实际配置/config.json --environment
```

原有 `valid`、`schema_version`、`compatibility_epoch` 保留，新增 `environment` 报告。`valid` 仅表示配置是否合法；`--environment` 下任一检查失败会返回非零退出码，详细原因看 JSON 中的各项结果。检查中断也返回非零，取消的探测标为未检查，不伪装成通过或 Docker 故障。CLI 的 WebSocket 和模型调用始终未检查。

请用与服务相同的运行用户和 Docker 环境执行；普通用户无法设置 Linux 容器属主时应报告失败，不能用宽松 chown 绕过。默认命令仍适合发布包的离线兼容检查，部署脚本不自动增加 `--environment`。默认配置解析错误保留原 CLI 提示；需要分享报告时使用 `--environment` 的脱敏 JSON，不分享含本机细节的原始错误。

写入探测的临时目录以 `.agentbox-diagnostic-` 开头，正常返回时清理。进程被强杀或清理失败可能留下该独立目录；应由管理员核对后处理，不自动扫描/删除其他目录。

## 接口与验收

| 接口 | 权限与行为 |
| --- | --- |
| `GET /api/diagnostics` | 管理员，原导出增加只读 `environment` |
| `POST /api/diagnostics` | 管理员，主动实例检查，返回版本 1 的检查报告 |
| `GET /api/diagnostics/ws` | 管理员、同源 WS，返回一条固定诊断响应并关闭 |
| `POST /api/sessions/{id}/diagnostics` | 登录且为空间属主；管理员也不能借此读取其他人的空间 |
| `GET /api/sessions/{id}/diagnostics/ws` | 同样的属主校验和同源 WS 检查，不启动空间 |

报告形状为 `{version:1, scope, checked_at, operation_id, checks:[{id,state,code,message,hint}]}`。HTTP 200 表示报告已生成，检查可以失败；鉴权和请求本身失败仍返回相应 HTTP 错误。错误码与诊断结果码是两个独立目录，诊断文案样本见 `internal/diagnostics/testdata/messages-v1.json`。

```bash
go test ./internal/diagnostics ./internal/credentials ./cmd/agentbox ./internal/server
npm run check
npm run build
npm run test:diagnostics
AGENTBOX_BROWSER_ONLY_DIAGNOSTICS=1 node scripts/test-browser.mjs
```

浏览器依赖配置见[开发指南](development.md)。CI 包含词典一致性与浏览器场景；Linux 文件系统脚本包含 diagnostics 包。验收使用合成账号、受控 Docker HTTP/运行时错误和临时数据目录，不删除真实镜像、不耗尽真实磁盘、不调用模型。root 与非 root 的 chown 行为需分别验证；真实生产代理和系统部署不由合成测试代替。
