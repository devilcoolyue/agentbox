# 可插拔决策插件设计

日期：2026-10-11。状态：已发布至生产 `v0.1.12-dev.collaboration.20261011.10`，本地功能及[真实账号协作验收](../milestones/decision-production-20261011.md)通过。本地实现按用户确认的 ASCII 流程接入：主辅分别选模，规则优先，Jev 可选，故障采用预设回退，执行配置冻结后不重新选择。实际接口和运维边界见第 9 节；验证记录见[专项验收](../milestones/decision-plugins.md)。

本文确定插件边界、开关语义和最小实施范围；任务路由原则、Jev 与 SemIf 的资料依据见[自动选模与按需协作](collaboration-model-routing.md)，执行模式见[轻量协作方案](collaboration-lightweight-research.md)。

## 1. 核心决定

采用“稳定的决策服务 + 可替换的建议提供方 + 原任务执行器”。Jev 只提供有界建议，平台决定最终执行绑定和调度。它不成为团队成员，不增加一个用户可见的规划阶段，不承担文件操作或运行恢复。

- **不用插件**：手动选择的模型直接执行；自动选择使用内置规则及预设回退。
- **使用 Jev**：先经过相同的权限、候选和规则检查，只有确实需要判断的自动任务才调用 Jev。
- **Jev 不可用**：在当前请求仍有合法执行资格的前提下，使用已配置的本地回退，不把整个协作功能关闭。
- **替换插件**：将来可增加 SemIf 等适配器，复用同一输入、调度和记录机制。

首版的“插件”是随 Go 二进制提供的独立适配器，通过配置热启停、选择和替换；增加新种类仍需要实现接口并发布版本。首版不建设任意代码上传、动态 `.so`、脚本安装或插件市场。Jev 是服务端插件，与安装到 Claude home 的 skills、用户 MCP、执行 Agent 的工具桥分开。

## 2. 用户界面与使用范围

管理员在“系统设置 → 智能决策”配置：

```text
Jev 辅助决策    [关闭 / 启用]
API Key        [已配置 · 更换 · 清除]
决策模型       [固定版本]
可供使用的用户 [沿用项目账号授权风格]
高级设置       [超时、调用限额]
```

保存只校验本地字段，不自动发送测试任务或产生费用。若提供“测试连接”，按钮须说明它会提交一条合成决策请求及记录费用，不发送项目正文；服务启动和后台健康检查不做付费探测。

普通用户保留原空间和输入框。模型可选具体名称或“自动”；协作团队里的主方和搭档各自可固定或自动。展开设置中只有一项“使用 Jev 辅助判断”，采用空间默认值，也能对本次任务关闭。插件未配置或用户无权使用时，不要求填写密钥。

管理员启用只表示该插件可用，不把既有固定模型空间变成自动选模，也不自动开启协作。普通模式不能因为插件建议而偷偷变成多 Agent；用户明确的主辅职责、CLI、账号和固定模型始终是约束。

全部角色固定时，Jev 调用为零。部分固定、部分自动时，仅为自动角色决策；固定角色的 CLI、账号、模型和强度保持不变。多个自动角色可以合并一次决策请求，但不得借此修改固定角色。

“自动选模”只允许改变用户交给系统选择的部分。用户仍可固定 CLI 类型、账号或推理强度；候选必须满足这些约束。自动模型可以来自同一 CLI，不能将自动选模等同于自动换主辅、换账号或跨 CLI。

| 本次选择 | Jev 状态 | 行为 |
| --- | --- | --- |
| 全部角色固定模型 | 任意 | 完全绕过 Jev，不产生分类调用 |
| 自动；不使用插件 | 任意 | 本地规则或预设回退 |
| 自动；使用 Jev | 可用且获准 | 规则不能明确决定时调用 Jev |
| 自动；使用 Jev | 关闭、未配置、撤权、超时或限流 | 本地回退，记录原因；不存在合法回退时才明确报错 |
| 已冻结执行绑定 | 后来关闭/修改 Jev | 保留原绑定，执行前照常复查账号授权和预算 |

“不用 Jev”和“不自动选模”是两件事。两者在界面与协议中分别记录，避免关闭 Jev 后反而丢失用户的模型选择。

典型配置及预期行为：

| 主方 | 搭档 | 本次插件选择 | 预期 |
| --- | --- | --- | --- |
| Claude，固定模型 A | Codex，固定模型 B | 开或关 | 使用 A/B，不调用 Jev |
| Claude，固定模型 A | Codex，自动模型 | 关 | 主方不变；从 Codex 获准候选中按规则选择，规则不能确定时用已冻结回退 |
| Claude，固定模型 A | Codex，自动模型 | 开 | 主方不变；只对规则尚未确定的搭档调用 Jev，失败用搭档的已冻结回退 |
| Codex，自动模型 | Claude，自动模型 | 开 | 两方分别运行规则；只将未决角色合并为一次 Jev 请求，最终整组绑定一次冻结 |

其中模型 A/B 为配置示例，不是内置等级；主辅可交换，同类型组合遵守相同规则。

## 3. 服务端结构

### 3.1 已确认的执行流程（ASCII）

```text
                         用户发送任务
                              |
                              v
                   校验并持久接收原任务意图
                  （同时冻结主辅约束、候选、
                      回退和策略版本）
                              |
                    按每个角色分别处理
                              |
               +--------------+---------------+
               |                              |
            固定模型                       自动选模
               |                              |
               v                              v
          保留指定绑定                 内置规则能明确决定？
               |                         |           |
               |                        能          不能
               |                         |           |
               |                         v           v
               |                     规则结果   允许使用 Jev？
               |                         |       |       |
               |                         |      是      否
               |                         |       |       |
               |                         |       v       |
               |                         |   调用 Jev    |
               |                         |       |       |
               |                         |   建议有效且足够明确？
               |                         |     |       | |
               |                         |    是      否 |
               |                         |     |       | |
               |                         |     v       v v
               |                         |  建议结果  预设回退
               |                         |     |       |
               +-------------------------+-----+-------+
                              |
                              v
               校验整组结果：原候选、约束、授权、预算
                              |
                 +------------+-------------+
                 |                          |
                通过                       不通过
                 |                          |
                 v                          v
       一次冻结主辅完整执行绑定       说明无法执行的原因
                 |
                 v
       原准入路径领取唯一执行资格
                 |
                 v
       Claude Code / Codex 执行任务
                 |
                 v
       返回结果、实际模型及用量记录
```

任务意图及其约束、候选、回退和策略快照在同一个接受事务中持久化，后续按角色读取该快照，不先接受再补读可变默认配置。图中的“允许使用 Jev”同时要求管理员启用、当前用户获准、本次任务选择使用、凭证可用及调用预算满足条件。超时、限流、连接异常、无效输出或弃权都进入预设回退；没有合法回退则进入“无法执行”，不无限等待或自动扩大候选。

仅规则尚未确定的自动角色进入插件；多个未决角色可合并一次 HTTP 请求。插件结果应逐角色校验，某一角色的建议无效不改变其他角色已经确定的结果。整组结果统一通过校验和 CAS 冻结后才允许准备执行。

### 3.2 插件装配与统一接口

```text
agentbox 决策服务
        |
        +-- builtin：内置规则与预设回退，始终存在
        |
        +-- jev：可选适配器，配置并启用后使用
        |
        +-- semif：后续可增加的自托管适配器
        |
        +-- 其他实现：遵守同一 Provider 接口
```

已增加 `internal/decision`，由 `Server` 注入。注册表是经过编译和测试的适配器集合，`builtin` 始终存在，`jev` 按配置可用。Jev HTTP 请求不占用 Agent 容器名额，也不持有配置写锁、空间锁、聊天提交锁、附件锁或 SQLite 事务。

已实现的提供方接口：

```go
type Provider interface {
    ID() string
    Capabilities() Capabilities
    Evaluate(context.Context, Request) (Evaluation, error)
}
```

`Evaluate` 返回业务建议和本次调用的已知用量/计费状态，即使返回 error 也不能丢弃已知费用证据。重放控制、超时、配置代次、预算和最终绑定属于决策服务，不让各适配器再实现一份任务调度。

| 数据 | 内容与约束 |
| --- | --- |
| `Request` | 决策 ID、用途、有限任务材料、问题模板版本、匿名候选引用及能力描述；不含账号密钥、home 路径或跨线程私有正文 |
| `Evaluation` | `suggest / abstain`、可选候选引用、类型化信号、后端实际版本、分数语义、已知用量和费用状态 |
| `Decision` | 平台最终选定的完整 CLI/账号/模型/强度绑定、来源 `manual / builtin / jev / fallback`、规则原因码、输入摘要及策略/候选版本 |

首版 Jev 适配器只实现 Choice，在同一次 HTTP 请求中分别判断未决角色的有限候选。Score 难度判断、Noul 分工信号尚未接入；接口不把上游具有的 primitive 直接宣布为本产品能力，也不把分布置信度当作正确概率。

首期插件用途只启用 **新协作任务持久接收后、首次执行配置冻结前的模型选择**。分工信号尚未实现；后续可先记录用于评估。真正改变任务数量、流程和后续子任务模型，需要轻协作调度器支持并另行开放。插件开关不会让现有固定双角色流程自动具有跳过规划或并行能力。

## 4. 配置与生效规则

已实现的持久配置包含内置回退策略、Jev 启用状态、使用授权、固定模型、超时、请求限制和服务端凭证。以下为最小示例，省略字段按第 9 节的默认值补齐：

```json
{
  "decision": {
    "default_provider": "builtin",
    "fallback_policy": "workspace_default",
    "plugins": {
      "jev": {
        "enabled": false,
        "gateway": "typesafe",
        "model": "jev-1.13.0",
        "timeout_ms": 1500
      }
    }
  }
}
```

超时 1500 ms 是 TypeSafe 官方接入的初始值，不是 Jev 时延承诺。接入服务支持 `typesafe / mindshub` 两个已适配的固定端点，不开放任意 URL 输入。Mindshub 建议单独设置 15000 ms；切换接入服务只更新网关选择，不自动修改已有超时。

本次任务选择覆盖空间默认值，但不能突破管理员的启用状态和授权范围；管理员关闭是硬闸门。任务接受时冻结有效策略、候选集合以及每个自动角色的具体回退绑定。未单独配置回退时，从用户已确认的空间/角色默认绑定解析；回退必须属于该角色的冻结候选且满足固定约束，否则不接受自动配置。可以显式配置强档回退，但不能因分类失败扩大预算或换到候选外的账号。

每个角色的策略只需记录下列信息；字段名称为开发约定，不是现有 API：

| 字段 | 固定角色 | 自动角色 |
| --- | --- | --- |
| `mode` | `fixed` | `auto` |
| `binding` | 完整的 CLI/账号/模型/强度绑定 | 决策后形成，不允许由插件直接写入 |
| `constraints` | 已包含在固定绑定中 | 用户明确固定的 CLI、账号、强度等范围 |
| `candidate_set` | 不使用 | 候选策略引用及接收时冻结的具体成员/版本 |
| `fallback_binding` | 不使用 | 接收时已解析的完整绑定，失败时不重新读取可变默认值 |

插件使用选择独立于角色策略记录为 `inherit / builtin / jev`。`inherit` 在接收时解析为空间默认或系统默认，实际生效值和配置 revision 一并冻结；之后空间修改默认值不改变该任务。

授权复查可以从原候选中剔除已经无效的成员，不能借配置更新扩大候选或重复调用分类器。若未冻结的建议被剔除，可使用仍获准的冻结回退；回退也失效则停止。整组绑定冻结后有角色失权时阻止执行，不自动换到另一个账号或模型。

API Key 仅保留在服务端受限配置中，沿用配置文件的原子保存和权限约束。设置读取只返回 `key_configured`，不返回原文或可恢复掩码；“不修改 / 设置 / 清除”有明确操作语义。普通用户只看到可用插件和用途，不获得凭证。插件凭证不进入 provider 的业务输入、浏览器、任务事件或 Agent 容器。

配置扩展必须覆盖 `Config`、持久结构、读取校验、`saveLocked`、`mutate` 的复制和回写、getter、`SettingsPatch`、`settingsView`；嵌套集合深拷贝。插件配置用独立 revision 防止多个设置页互相覆盖，通过 `Config.mutate` 原子保存后才热生效。`SettingsPatch` 未出现的字段保持不变。

## 5. 接收、冻结与旧协议兼容

当前普通 chat v1 要求客户端冻结具体 model，model/effort 属于输入指纹，浏览器还逐项核对回执。当前协作步骤也要求实际参数完全匹配角色配置。因此不能把 `auto` 或 `jev` 塞进原 model 字段，不能先接受原请求再静默改模型。

首期接入**版本化的新协作自动意图**：分别保存用户请求的固定/自动策略和最终具体绑定。能力声明明确是否支持该协议；旧协作请求和旧任务继续原语义。普通固定模型 chat v1 不接插件；普通对话的自动选模后续单独扩展持久协议，不把它算作首期现成功能。

已实现的新请求持久接收只确认用户意图，尚不允许启动执行器。服务端按以下顺序处理：

1. 冻结任务输入、scope、线程、来源上下文、各角色约束、路由策略/候选版本和预设回退；以原请求 ID 去重。
2. 用 CAS 领取决策资格，需要外发时先登记唯一 `decision_attempt`，再在事务外调用插件。同一请求的同一决策代次最多自动派发一次分类调用。
3. 合并固定绑定、规则结果、有效插件建议和需要的回退，校验所有角色约束及最新授权，通过一次 CAS 写入整组不可变结果（`collaboration_decisions.result_json`）。即使两个进程竞争，也只有一个决定生效；不得先启动一方，再等另一方的选模结果。
4. 由同一任务的原准入路径领取执行资格。只有明确的 fresh/claim 成功才能启动 CLI；决定本身不是第二份执行资格。
5. 创建/动作响应丢失时查询原 ID；刷新、SSE、轮询和恢复只读取既有决定，不能重选模型或重新派发任务。

新自动意图必须同步进入网页待确认存储与回执校验，保留身份、空间、线程隔离及迟到响应检查，不能复用旧 v1 envelope 的字段含义。新的表/列走新增迁移，不能修改已经使用的 013/014。

后续在子任务边界选模时使用新的步骤绑定，而非反复调用当前 `configure`。当前 configure 会撤销参与者、重建配置代际和规划，不能作为低成本路由接口。

## 6. 关闭、错误与恢复

| 情况 | 处理 |
| --- | --- |
| 未开启/没有凭证/不在插件使用范围 | 不发请求；自动任务使用内置策略 |
| 规则足够明确 | 直接选择，不调用 Jev |
| 超时、429、网络异常、无效类型或非法候选 | 在当前仍有效的任务上 CAS 冻结回退；记录插件错误，避免强制用户点击“重试决策” |
| 信号不足或低于经评估的阈值 | 作为弃权处理，使用预设回退；不追加一个必须调用的高级“评判模型” |
| 禁用发生在尚未派发时 | 阻止外发，使用内置策略 |
| 禁用发生在已登记外发/等待返回时 | 撤销等待并冻结回退；远端可能已处理和收费，保留调用记录 |
| 插件结果在回退之后到达 | 只补齐该次调用的费用等证据，不改变模型、不启动第二次执行 |
| 已冻结模型或 CLI 正在运行时关闭插件 | 继续原步骤；以后新的自动决策走内置策略，旧绑定仍受账号撤权和预算检查 |
| 配置版本变更、候选被撤权 | 未冻结决定重新检查有效性；已冻结绑定不能偷偷替换，无权执行时沿用原阻止机制 |
| 服务重启、执行结果不明 | 沿用当前暂停/uncertain 与显式恢复规则，不能借插件回退自动重跑 |
| 数据库、持久化或业务结算失败 | 属于核心执行故障，不能当成普通插件不可用而放行 |

插件有并发上限；连续失败后短期跳过远端，后续新任务再有限尝试，不做定时付费探活。HTTP 客户端首期关闭自动重试，首个尝试未能确定失败前不发第二次收费请求。

配置生效与外发资格领取共用启用代次检查。已领取外发资格的请求算在途；关闭会撤销本地等待，但不能承诺撤回远端已接收的请求。后续尝试不能沿用旧凭证代次。

## 7. 决策费用与“不阻塞”的边界

每个外发尝试以 `decision_attempt_id` 归因，只认领一次用量。成功的建议可以不被采用，费用仍可能存在；超时也不能写成“确定免费”。Jev 错误返回如有已知用量同样保留。

新付费插件接入必须包含决策调用的独立用量种类和任务关联，并纳入任务预算与用量视图；不伪装成 Claude/Codex 的输出 token，不改变原聊天费用的含义。精确扣费只有在有确定计费依据时才进行。

调用前依据固定价格、请求上限和提供方计费规则预留可证明的费用上限；无法得到保守上限、价格未知或预算不足时直接不调用插件。请求大小上限必须由适配器实际执行，不能只写在配置里。

分类费用未知时，保留待核对记录和预算占用；如果扣除占用后仍满足后续执行准入，可以使用已冻结回退继续，否则按原预算规则停止。未知占用不能冒充实际费用，不能无依据释放。这里需要增加决策预算的明确“预留”语义，不能直接把当前 CLI 的 `usage_incomplete` 闸门放宽。

这样，Jev 故障本身不会强制阻塞任务；预算不足、权限变化和执行状态不明仍按原规则处理。“可选”不意味着绕过这些核心条件。

## 9. 本次实现与运维说明

### 实际选择策略

在原空间选择“多 Agent 协作”，展开团队配置，为主方和搭档分别选择固定模型或自动。自动角色仍有具体回退模型，CLI、账号、推理强度保持用户设置。普通聊天继续发送具体模型，不接入自动意图，也不会经过 Jev。

首版内置规则只在**合法候选唯一**时直接选择；多个候选不能明确区分时使用被冻结的回退。没有根据模型名、价格或任务关键词猜测强弱，也尚未承诺“简单任务必选便宜模型”。能力分档和更准确的难度判断需后续代表性任务评测。

Jev 只收到未决角色的匿名候选引用、有限描述与任务材料，不收到账号密钥、home 路径或完整绑定。两个未决角色合并一次 HTTP 请求。每个 Choice 包含 `abstain`；响应必须匹配固定模型、返回完整合法分布且有唯一最高选项。当前接受门槛是分布 confidence `>= 0.65`，这是**待校准的策略阈值，不代表 65% 正确率**。单个角色的缺失、非法或低置信建议只使该角色回退。

管理员已配置的模型/Agent 单价可随候选描述一并冻结，作为成本参考；不以价格推断能力，也不把单价当作任务总费用。Jev 提示词要求简单任务在能力已足够的候选中优先较低已知成本，复杂任务先考虑能力；缺少可比较材料时弃权。当前尚无本项目任务能力分档，是否能有效降低成本仍属 DP-12 的待验证内容。

固定角色、唯一候选、停用、无密钥、无权、请求超限或预算不足均不调用 Jev。最多 2 个角色，每角色至多 254 个候选；候选更多时保留完整冻结候选并回退，不截断候选来凑请求。

### 配置与 API

默认值：`default_provider=builtin`、`fallback_policy=workspace_default`、Jev 关闭、授权 `admin`。保存设置只写本地配置，无付费探测。

| Jev 字段 | 默认值 | 允许范围 |
| --- | --- | --- |
| `gateway` | `typesafe` | `typesafe / mindshub`；缺省仍使用官方服务 |
| `model` | `jev-1.13.0` | 仅此已核查的固定版本；不接受 latest 别名 |
| `timeout_ms` | 1500 | 100～30000 |
| `max_request_bytes` | 32768 | 1024～65536；限制序列化后的实际请求 |
| `max_concurrency` | 2 | 1～16 |
| `access` | `{"mode":"admin"}` | `all / admin / users`，指定用户须存在 |

管理员 `GET /api/settings` 的 `decision` 返回独立 `revision`、默认策略和 `plugins.jev`，只含 `key_configured`，没有密钥原文。通过原设置接口部分更新；例如停用且保留凭证：

```json
{
  "decision": {
    "expected_revision": 3,
    "plugins": {
      "jev": {
        "enabled": false,
        "api_key": {"action": "keep"}
      }
    }
  }
}
```

`api_key.action` 为 `keep / set / clear`，仅 `set` 携带非空 `value`。`expected_revision` 使用读取到的值；过期返回 409，其他设置未出现则保留。成功落盘才切换生效代次并撤销旧等待。

已有密钥时，切换 `gateway` 必须在同一次更新中明确 `set` 新密钥或 `clear` 原密钥，`keep` 或省略密钥操作会被拒绝。前后端均检查此约束，避免将一个服务的凭据发送给另一个服务。页面只显示“已配置”，不会读取或回填密钥。Mindshub 使用编译固定的 `https://api.mindshub.ai/v1/decisions`，传输模型别名为 `jev`，响应仍须验证为 `jev-1.13.0`。

| 接口 | 用途 |
| --- | --- |
| `GET /api/collaboration/options` | 返回 `automatic_intent_version:1` 和 `decision:{default_provider,jev_available}` |
| `GET /api/sessions/{id}/collaboration/decision-default` | 读取空间默认 `inherit / builtin / jev` |
| `PUT /api/sessions/{id}/collaboration/decision-default` | 保存 `{scope,provider}`；只影响新请求 |
| `PUT /api/collaboration/runs/{request}` | 原协作创建体可增加下述 `decision`；`roles` 保留固定绑定或自动角色的具体回退 |
| `GET /api/collaboration/runs/{run}` | 查询原请求、当前具体配置、费用及 `decision:{state,revision,snapshot,result,attempt}` |
| `POST /api/collaboration/runs/{run}/decision/reconcile` | 用 `{scope,expected_revision}` 复核已存费用证据；revision 是当前任务 revision |

创建体的扩展字段示例：

```json
{
  "decision": {
    "version": 1,
    "provider": "inherit",
    "roles": {
      "coordinator": {"mode": "fixed"},
      "executor": {"mode": "auto"}
    }
  }
}
```

省略 `decision` 保持旧固定模型协议。原请求与最终绑定分别保存；查询、刷新、SSE、响应丢失恢复和费用复核均不重分类。任务选择 `inherit` 在接收时按空间默认、再按系统默认解析，之后不随设置漂移。

### 费用与故障处置

TypeSafe 官方接入只认 `jev-1.13.0` 的已核查价目：每百万输入 token **0.042 美元**，输出免费；来源为 [TypeSafe 模型文档](https://docs.typesafe.ai/models)，核查日期 2026-10-11。按该版本完整 64k 上限保守取 65,536 token，每次外发先预留 **2,753 微美元**，不使用字节数猜 token。实际已知费用按现有账本的整数微美元规则计价，价目版本随用量记录；未知版本或无法满足预留预算时不调用。

Mindshub 当前公开 Jev 输入、输出及缓存费用为 **0**，受其公平使用限制；依据为 [Decisions 的限制与计费](https://docs.mindshub.ai/inference/decisions.md#limits-and-billing)和 [Jev 计费说明](https://docs.mindshub.ai/inference/billing.md#jev-decisions)。该网关费用上限为 0，仍记录已确认的输入/输出用量与调用次数，费用来源标为 `mindshub`。免费不等于不消耗服务方的请求或 token 限额。超时、缺失用量或版本不合格仍记为未知；即使没有金额预留，页面也显示“决策调用用量尚待核对”，不能伪造确定的零 token 记录。

任务费用包含 `decision_cost_micro_usd`、`decision_reserved_micro_usd`、`decision_partial`、`decision_calls`。超时不等于免费；预留未核清时继续占用任务和用户额度。余额扣除占用仍满足原准入才允许回退执行。适配器不重试、不跟随重定向；并发满或连续失败熔断时，新任务采用本地回退，无后台付费健康探测。

若显示决策费用结算失败，先修复存储/账本故障，再使用“核对决策费用”或上述 reconcile 接口。该接口只重放服务端已保存的已知计费证据，不接受浏览器填写 token/金额，不重新调用 Jev 或启动 CLI。没有确定证据的超时占用不能通过此接口清零；已有冻结绑定也不会变化。核对成功后仍按任务原暂停原因处理，必要时显式恢复。

普通进程重启会暂停未完成决定，显式恢复仅采用原冻结回退，不自动重发分类请求。**完整备份恢复后，尚未冻结执行绑定的自动任务需取消并重新创建**；不能借重新配置或恢复复用旧实例的路由现场。系统备份缺少项目文件，遵守现有不可交付规则。已有决策费用及未知占用不因恢复、取消或删除任务而伪造为零。
