# 受限文件访问

`internal/safefs` 为 Linux 服务端和 macOS 开发环境提供基于目录句柄的文件操作。HTTP 层负责属主和 scope 校验，文件系统层负责把实际 I/O 限制在已授权的目录内。只做字符串路径检查或逐段 `Lstat` 后返回绝对路径不能提供这个保证。

## 信任边界

- `data_dir`、会话目录的父级、服务端 staging 目录由服务管理，不能直接挂进用户容器。
- 容器能修改 workspace、home、shared 中的文件、目录和符号链接；每次访问都按不可信输入处理。
- 管理员配置的外部 `credentials_dir` 是显式授权的凭证根，内部条目仍经受限文件接口读写。
- HTTP 入口从 `data_dir` 打开，再用 `Sub` 定位授权区域。Agent 播种从服务拥有的 home 父目录打开，再固定 home 本身。

## API 规则

`Open` 只接受可信根；`Sub` 固定不可信后代目录。`Sub` 每层比较检查时与打开后的文件身份，拒绝符号链接和发生替换的目录。所有后续操作使用句柄，不再拼回绝对路径调用 `os.Open/WriteFile/Rename`。

`OpenFile` 只读普通文件，最终组件使用 `O_NOFOLLOW`；同时用 `O_NONBLOCK` 避免普通文件被替换成 FIFO 后阻塞，再用打开后的 `f.Stat` 确认类型。目录读取时立即通过受限根获取元数据，避免 `DirEntry.Info` 延迟读取旧绝对路径。

`WriteAtomic` 在固定的父目录中创建随机 `O_EXCL` 临时文件，写入、设置属主/权限/时间并同步，再原子替换目标。写入失败不会截断原文件；替换目标 inode 也避免通过已有硬链接修改另一份文件。编辑器保存保留原有可执行位，但替换 inode，因此其他硬链接继续指向旧版本，这是有意的安全行为。

移动与重命名使用固定父目录的 `renameat` 系列调用；Linux 使用 `RENAME_NOREPLACE`，macOS 使用 `RENAME_EXCL`，目标冲突不会覆盖。删除通过 `os.Root.RemoveAll`，不沿链接删除目录外目标。修改普通文件或目录元数据使用已打开文件描述符，避免路径版 chown/chmod 的竞态。

`ReadFile` 支持有意截断的预览，配置和凭证使用 `ReadAll` 或专用有界读取并在超限时返回错误，不能将截断配置覆盖写回。

## 已迁移入口

| 入口 | 根与行为 |
| --- | --- |
| 文件列表、编辑、下载、目录创建、移动、重命名、删除 | workspace/shared 固定句柄，保留 scope 与属主检查 |
| 上传、解压、工作区 ZIP | 容器挂载之外先完整解压；验证成功后通过句柄合并，拒绝目标链接；压缩包跳过链接/特殊文件，并限制解压字节 |
| Git 仓库发现与完整文件读取 | 从 data_dir 打开；Git 命令仍在容器执行 |
| HTML 预览 | 每次从 data_dir 重开授权子目录，拒绝授权后被替换成链接的目录；继续使用 CSP sandbox |
| 技能列表、详情、文件、复制、安装、删除 | 固定技能根；清单可显示链接但不沿链接读取/复制；保留 mtime 更新语义 |
| 粘贴附件写入和过期清理 | 固定 shared 子目录；保留历史引用保护 |
| 模板、凭证、默认模型、内网提示和 HUD 播种 | 固定 home；模板链接原样复制供 CLI 使用，服务端不沿链接播种 |
| OAuth 凭证同步与刷新写回 | 固定 home/账号根，单次文件读取同时取得内容和元数据，随机临时文件原子替换并保留 mtime 收敛规则 |
| 终端用量 transcript 读取 | 目录发现、打开与解析使用受限根；inotify 仅作为尽力触发器，内容读取仍受同样约束 |

上传的“完整解压后合并”不等于整个目录事务：格式或解压失败不会改动工作区，合并阶段遇到磁盘/目录冲突则可能已经合并部分条目。`clear=1` 也不会提供跨目录原子事务，不能以此替代备份。

## 验证与限制

回归测试覆盖符号链接拒绝、并发目录替换、已固定目录被重命名、硬链接安全保存、失败写入保留旧内容、原子目标冲突、ZIP/TAR 目标链接、解压限额、HTTP 保存时替换父目录、预览授权目录替换、技能父级链接以及凭证 `.tmp` 链接攻击。

这个边界不承诺隔离宿主机管理员或可自行挂载设备的特权进程；Docker socket、bind mount 策略和宿主机目录属主仍是部署安全前提。共享凭证对容器内使用者可读的产品边界也没有改变。
