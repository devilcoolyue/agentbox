# 透明内网访问实施记录

目标：对话与终端无需代理提示或专用环境变量，直接访问用户允许的内网 IP、域名和 TCP 服务。

## 实现边界

- 复用 abox-link 的 WebSocket / yamux TCP 隧道、客户端 DNS 和最终白名单检查。
- 工作空间网络命名空间内独立辅助容器捕获 agent UID 1000 的 TCP 与 DNS；辅助进程自身连接不再次捕获。Agent 容器不增加权限。
- 显式域名使用按用户持久化、不复用的虚拟 IPv4 地址；实际域名交给客户端连接。
- 路由快照在掉线后保留，移除的目标仍捕获并拒绝，避免旧缓存或失效隧道落到服务器内网。
- HTTP 账号出口桥接与透明转发共用目标判定；工作空间身份与账号身份分离。
- 第一版 TCP / IPv4；内网域名 AAAA 返回空结果，UDP / ICMP 不作为支持范围。
- 未升级客户端保持兼容代理模式；透明网络就绪与客户端在线分别报告。

## 验收清单

- [ ] Linux Docker：无专用 env、无说明文件，直接 HTTP / 原生 TCP / 域名访问。
- [ ] 两个用户访问相同地址互相隔离，端口白名单仍有效。
- [ ] 账号出口代理与内网同时启用，公网仍按账号出口。
- [ ] 掉线、重连、规则撤销、服务重启、辅助进程重启不误连。
- [ ] Docker 网段冲突、IPv6、不支持能力明确报错。
- [ ] 生命周期、控制台和客户端 UI、兼容迁移与部署文档。
- [ ] Go build/test、前端检查/构建、真实容器集成验证。

## 已完成的验证（2026-09-26）

- macOS 上 Go 全量 build/test 与 TypeScript 检查/构建通过；新增网络模块与服务端、客户端、工作空间 race 测试通过。
- 本机 Docker Desktop 的 Linux/arm64 daemon 上，合成数据集成测试已验证 IPv4、客户端域名解析、原生 TCP、双用户相同地址隔离、端口限制、断线／重连、辅助进程重启、账号 HTTP/CONNECT 出口共存与出口失败不回退、域名撤销、服务重启和空间删除。
- 浏览器合成 API 回归通过，新增状态和 TCP 检查流程可操作；桌面截图已检查。
- 客户端 linux/amd64、linux/arm64、darwin/amd64、darwin/arm64、windows/amd64 构建通过（运行实测是 Linux/arm64）。
- 网络辅助镜像构建脚本实测通过。不涉及生产部署、真实账号或模型调用。

实现选择：辅助进程捕获 UID 1000 的所有 IPv4 TCP，再按目标选择隧道或原有直连出口；DNS 也由它分流。公网 TCP 因此多经过一次本地进程转发。辅助进程故障会暂时影响该空间的 TCP/DNS，规则保留且由 Docker 重启辅助进程。账号 HTTP 代理仍按原有环境变量使用，桥接通过实际容器 IP 与当前账号授权确定用户。
