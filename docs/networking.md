# 出口代理与内网隧道

[返回文档目录](README.md) · [项目首页](../README.md)

| 功能 | 用途 | 请求去向 |
| --- | --- | --- |
| 账号出口代理 | 为账号指定上网出口 | 容器 → 服务端 HTTP 桥接 → 代理池中的代理 → 外部服务 |
| abox-link 透明模式（默认） | 让云端工作空间直接访问获准的内网地址 | 空间网络辅助容器 → 用户隧道 → 你的电脑 → 内网服务 |
| abox-link 兼容模式 / 端口映射 | 旧客户端或显式代理、映射访问 | 容器 → 服务端 SOCKS / TCP 映射 → 你的电脑 → 内网服务 |

两者可以同时使用，分别控制外网出口与按需内网访问。默认网关地址 `172.17.0.1` 只是 Docker 默认网桥的常见值，部署前应核对实际网络。

## 账号出口 IP 代理

给账号绑一个出口 IP：绑定后，**这个账号的一切官方请求都从该 IP 出去**——容器里
`claude`/`codex` 打的模型接口，以及服务端代发的 OAuth 换令牌、订阅查询、Key 连通性
探测。多个订阅账号共用一台服务器时，这是把它们的来源 IP 分开的办法。

在「系统设置 → IP 代理」里维护代理池（增删改、连通性探测、批量导入导出），再到
「账号池 → 编辑 → 出口 IP 代理」为账号选一个。改动对新对话与新开的终端立即生效，
不必重启容器。

几个需要知道的行为：

- **代理池里多是 SOCKS5，而容器里的 claude 是 Node 客户端，只认 http(s) 代理。**
  所以 agentbox 在网桥网关上起一个本地 HTTP 代理（`proxy_bridge`），容器只跟它说
  HTTP 代理协议，SOCKS5 那一段由服务端走完。代理池非空时自动启动。
- **绑了代理就绝不退回直连。** 代理停用、配置坏掉或桥接没绑上时，请求会直接报错，
  而不是悄悄改用服务器自己的 IP——后者正是绑定代理要避免的事。
- **注入的是全局 `HTTP(S)_PROXY`**（大小写各一份，外加 `NO_PROXY` 放行本机与网桥）。
  遵循这些代理环境变量的 `git clone`、`npm install` 等命令同样走这个出口；这不是容器网络层的强制流量重定向。
- 每个账号在桥接上的口令由服务端 `auth_token` 派生，互不相同；桥接要求提供对应账号的口令。
  修改 `auth_token` 并重启服务后，口令随之轮换，已运行进程需更新环境。
- 批量导入支持 `scheme://user:pass@host:port`、`host:port:user:pass`、`host:port`
  三种写法，可用 `#名称` 结尾；不写协议按 SOCKS5 处理。导出的文本**含密码明文**。

## 内网反向隧道（abox-link）

云端容器默认到不了「只有你本机能连」的内网（公司内网、局域网设备、本地数据库）。
开启 `tunnel` 后，你在**自己的机器**上跑 abox-link，通过 WebSocket 连接服务器。真正的内网域名解析与目标拨号都在本机客户端执行，最终受本机放行列表限制。默认的透明模式和兼容模式使用不同的容器入口：

```text
透明模式：容器普通 TCP/域名 → 空间网络辅助容器 → 用户隧道 → 本机 abox-link → 内网
兼容模式：容器显式 socks5h / 端口映射 → 服务端代理 → 用户隧道 → 本机 abox-link → 内网
```

透明模式下不应根据有没有 `AGENTBOX_INTRANET_PROXY` 判断连接是否就绪；看网页的空间网络状态。兼容模式需要显式使用代理，且已有 Shell 不会自动继承新环境。下面分别说明。

- 开关与状态都在 Web UI：管理员在 系统设置→安全与访问 启用（**即时生效**，无需重启）；
  所有用户侧栏可见「内网隧道」入口——在线状态、活动端口映射、接入指引与各平台
  abox-link 下载（把交叉编译好的二进制放进 `data/abox-link/` 即出现下载按钮）
- 构建客户端：`go build -o abox-link ./cmd/abox-link`

### 透明内网访问

默认推荐透明模式；兼容代理模式保留给旧客户端或特殊场景，暂不推荐。服务端与客户端都启用透明访问后，对话和终端直接使用放行的内网地址，例如：

```bash
curl http://gitlab.corp.local
mysql -h 10.20.0.5 -P 3306
```

不需要专用代理环境变量或 Agent 读取使用说明。第一版支持 IPv4 / TCP（HTTP、Git、SSH、常见数据库），不提供通用 UDP、ICMP 或 IPv6 隧道，`ping` 不能用于判断是否可用。

管理员先在 Docker 所在的 Linux 服务器构建辅助镜像：

```bash
./scripts/build-network-image.sh
```

再到「系统设置 → 安全与访问 → 内网反向隧道」启用隧道及透明访问。网络控制地址默认使用 SOCKS 监听主机的 `1082` 端口，容器通过配置的代理主机访问它；该端口与原有 SOCKS 端口都应只对容器网络开放。可配置 `tunnel.network_bind`、`tunnel.network_image`，镜像默认 `agentbox-network:latest`。

本机 abox-link 面板勾选「透明内网访问」，填写放行列表并保存、启动。命令行对应：

```bash
./abox-link --server https://box.example.com --user alice --transparent \
  --allow 10.20.0.0/16 --allow gitlab.corp.local:443
```

- 透明目标来自客户端的 **放行列表**，端口映射仍作为独立的兼容功能。支持 IPv4 网段、IPv4 地址、精确域名和 `主机:端口`；不支持通配域名或接管默认路由。
- 域名在工作空间中映射到专用虚拟地址，真正的解析与拨号仍在本机客户端执行。TLS 主机名保持不变。只给域名配置 443 时，对该域名的其他端口连接失败。
- 不同用户的同一地址分别走自己的隧道。客户端仍执行最终白名单校验；服务端的路由不能扩大客户端授权。
- 公网流量继续使用原有出口。设置了账号出口代理的软件，其 HTTP/CONNECT 请求也按所属工作空间选择内网隧道；公网继续走账号代理，代理失效不会回退直连。
- 对话页可查看内网状态；隧道页分别显示客户端在线状态、各运行空间是否就绪和可用目标。「检查连接」验证客户端到目标的 TCP 连接，不能代替工作空间就绪状态。
- 规则更新最多经过一个约 2 秒的同步周期；以工作空间「网络就绪」为准。既有 Shell 的新连接无需重开终端。已经建立的 TCP 连接不承诺无缝切换。
- 隧道掉线或规则撤销后，旧目标仍保留捕获规则，连接明确失败。历史域名的虚拟地址不复用，避免 DNS 缓存误连其他服务。快照保存在 `data/users/<user>/network.json`，包含内网目标，应作为用户配置备份。
- 与 Docker 网络重叠的网段会明确报告冲突；需缩小目标范围或调整 Docker 网段。回环、链路本地和虚拟地址段不能作为透明目标；访问本机回环服务可继续使用端口映射。

每个工作空间额外运行一个无用户目录挂载的网络辅助容器，仅它获得网络管理权限；Agent 容器仍为普通用户。辅助进程故障时规则继续保留，可能暂时阻断工作空间 TCP/DNS，页面会显示未就绪。服务重启会恢复运行空间的网络管理；停止／删除空间时同步清理辅助容器。

服务端和新版客户端未指定模式时默认透明访问；显式保存的 `transparent:false` 保留兼容代理模式（暂不推荐）。隧道总开关仍单独控制，默认关闭，不会因模式默认值启用联网。新版客户端启用透明模式连接旧服务端时会明确报错，需先升级服务端。旧客户端可继续使用 SOCKS／端口映射。若需切回兼容模式，先停止所有运行空间，再关闭透明访问并重新启动空间，让网络命名空间一并更新。

### 用法一：本机控制台（默认）

abox-link 不带任何参数运行时，会在 `127.0.0.1:7801` 起一个本机控制台并自动打开浏览器：

1. 在 agentbox 的「内网隧道」页面点**生成配对码**（10 分钟有效、只能用一次）；生成后自动复制，也可点配对码右侧的复制图标再次复制
2. 双击运行 abox-link，把配对码粘进去——**不用填服务器地址，也不用输密码**
3. 在页面上增删放行规则与端口映射，点「启动」；可勾选**开机自启**与**启动时自动连接**

页面顶部是一条 `agentbox — 本机 — 内网` 的电路：中点就是你这台机器，也是放行规则
生效的那一点（挂着当前规则数）。状态按腿区分——凭证失效只断朝服务器的那一侧，
连接中也只点亮 agentbox 那头的灯，两端都亮才表示电路真的通了。宽屏下运行日志与
规则并排，改完点「保存并应用」后隧道按新规则重连，重连过程在同屏就能看到。

配置存在 `~/.abox-link/config.json`（0600）。配对换回来的是一枚会话令牌，**密码不落盘**；
改过密码后令牌失效，控制台会提示重新配对。控制台只监听回环地址，并要求
`X-Abox-Panel` 头与回环 `Host`/`Origin`，挡掉 DNS 重绑定与网页发起的跨站请求。

开机自启按平台落地为 systemd 用户单元 / LaunchAgent / 登录计划任务，均**不需要管理员权限**。
（Linux 上未开 linger 时注销即停，控制台会把这句提示显示出来。）

### 用法二：命令行（无头机器 / 脚本）

带 `--server` 时使用前台无头模式，并自动重连：

```bash
ABOX_PASSWORD='REPLACE_WITH_YOUR_PASSWORD' ./abox-link \
    --server https://box.example.com --user alice \
    --allow 192.168.1.0/24 --allow db.corp.local:5432
```

`--allow` 可重复，支持 CIDR、主机名、`主机:端口`；放行判断在本机侧强制执行，
即使服务器被攻破也无法把你的机器当作任意内网跳板。每条连接都会打印审计日志。
两种模式共用同一套白名单与重连逻辑，只是前者把开关做成了按钮。

- **兼容代理模式**下，隧道在线时，容器内自动注入 `AGENTBOX_INTRANET_PROXY=socks5h://<user>:<secret>@<gateway>`。
  它**不是**全局 `HTTP_PROXY`（避免模型 API 等全部流量绕行你的家宽），智能体按需使用，例如
  `curl --proxy "$AGENTBOX_INTRANET_PROXY" http://gitlab.corp.local/...`。
- **兼容模式的变量**随每次 exec 注入，对话每回合都取当前值；终端因为附着在常驻 tmux 上，**已经在跑的
  窗格保持它启动那一刻的环境**（进程改不了自己的环境变量）。镜像默认关闭了 tmux 的前缀键，不能直接使用 `Ctrl-b c`。所以工作空间先开、隧道后连时，
  在旧窗格里会看不到该变量。重连终端会把最新值写进 tmux 全局环境，此时开一个新窗口
  （在 Shell 中执行 `tmux new-window`）即可拿到；在旧 Shell 中只重启智能体不会更新它继承的环境；隧道断开同理会被清除。
- **端口映射（`--map`）**：psql / mysql / redis-cli 及各类数据库驱动不认 SOCKS，
  用 `--map 3306=10.0.1.5:3306`（可重复，每用户最多 16 条）在网关上开一个原生
  TCP 端口，直通指定内网目标：

  ```
  容器 --tcp--> 172.17.0.1:3306 --隧道--> 本机 abox-link --> 10.0.1.5:3306
  ```

  映射目标自动并入白名单；监听端口须 ≥1024，绑定结果在连接握手时逐条回执到
  abox-link 日志。裸 TCP 无凭证，服务器按**来源 IP** 隔离——只有属主用户自己的
  容器（和宿主机）能连上映射端口，其他用户的容器一律拒绝。隧道在线时容器内注入
  `AGENTBOX_INTRANET_MAPS=<监听地址>=<内网目标>,...`，智能体据此直连。

### 常用客户端参数

| 参数 | 用途 |
| --- | --- |
| `--server` | 服务端 HTTPS 基础地址；指定后进入无头模式 |
| `--user` | 登录用户名，与 `ABOX_PASSWORD` 搭配 |
| `--token` | 使用已有会话令牌，跳过密码登录 |
| `--transparent` | 默认 true；`--transparent=false` 使用兼容代理模式（暂不推荐） |
| `--allow` | 放行 CIDR、主机或主机端口，可重复 |
| `--map` | `监听端口=目标主机:端口`，可重复 |
| `--daemon` | 本机面板运行但不自动打开浏览器 |
| `--addr` | 本机面板地址，默认 `127.0.0.1:7801`，仅允许回环 |

默认拒绝所有目标，至少添加一条白名单或映射才能启动。同一用户只保留一条在线隧道，连接状态以网页和客户端日志为准。

配置文件默认在 `~/.abox-link/config.json`，可通过 `ABOX_LINK_HOME` 指定目录。令牌过期或被撤销后，本机面板需要重新配对；有密码的无头模式可重新登录。

网页下载目录为实际 `<data_dir>/abox-link/`；`scripts/build-clients.sh` 默认输出到仓库的 `data/abox-link/`，数据目录自定义时需复制过去。跨平台构建和发布顺序见[部署手册](../deploy/README.md#镜像与客户端更新)。
