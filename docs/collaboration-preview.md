# 多 Agent 协作开发预览

C1 双角色协作已具备后端与页面端到端流程，当前作为默认关闭的开发预览。当前实现和未完成项见[实施记录](milestones/collaboration.md)，目标架构见[设计方案](architecture/agent-collaboration.md)。本说明描述当前行为，不代表正式发布验收。

## 直接执行与协作复核（schema 16，生产开发预览 `.15`）

发送前可在同一团队设置选择“直接执行”或“协作复核”。直接执行只使用执行者配置：自行处理需求，必要问题直接问用户，再做平台验证并整理结果；不单独调用规划或评审模型。验证失败或仍有未完成要求时按预算/返工上限返回执行者修复，不能作为成功交付。结果明确标记“未做独立模型评审”；没有配置验证命令也不显示测试通过。

协作复核沿用主方规划、辅方实施、主方评审；新任务增加计划代码地图、按原生线程确认边界增量交接，以及平台生成的有界快照 diff。差异缺失、二进制或超大文件会明确标记，模型需要继续核实材料。Jev 仍可选，只参与实际角色的自动选模；策略由用户选择，不由 Jev 偷偷改动。

旧请求没有 `workflow` 字段时保留原流程；当前任务重新配置不允许切换策略，需新建任务。详情与恢复边界见[协作减重实施记录](milestones/collaboration-lightweight-20261012.md)。以下三阶段说明适用于协作复核及旧任务。该改动已发布生产 `.15`，schema 16；旧任务和已有草稿继续保留原策略。


## 可选 Jev 决策插件

开发版在“系统设置 → 智能决策”提供接入服务选择：TypeSafe 官方或 Mindshub。选择对应服务并设置其 API Key，保存不会发送测试请求。已有密钥时切换服务，须明确设置新密钥或清除旧密钥；原服务的密钥不会随网关切换直接复用。

Mindshub 当前公开 Jev 调用免费，受其公平使用限额约束；建议在高级设置中将决策超时设为 15000 毫秒。切换服务不会自动改变已有超时，TypeSafe 默认仍为 1500 毫秒。在协作团队里将需要选择模型的角色设为“自动选择模型”，再启用“使用 Jev 辅助判断”；固定角色、唯一候选或不满足调用条件时不调用 Jev。具体回退模型保留可见，实际选择及决策用量在任务消息中显示。完整配置、计费与恢复说明见[决策插件文档](architecture/decision-plugins.md)。

## 空间内协作（schema 14 开发版）

进入空间的对话页，在输入框旁把“普通对话”改为“多 Agent 协作”。点击团队摘要即可分别设置主辅、账号、模型与推理强度，支持交换。项目固定为当前空间；有单一可识别仓库时给出路径建议，也可展开设置手动改路径。发送前可以查看携带的对话上下文，关闭携带后只使用本次需求。附件暂不支持进入协作，页面会保留并明确提示。

发送后留在当前对话。任务消息里确认计划、答复、补充要求、暂停和继续；“查看过程”展开交流、画布和变更。补充要求在当前步骤结束且结果确认后重新规划。默认仍需确认新计划。普通模式可继续源空间对话，输入目标会明确显示，不把普通消息猜成任务答复。

评审通过后，“应用到当前项目”先展示差异，再要求明确确认。请先停止空间；源仓库产生新提交/未提交修改时拒绝覆盖。应用保留原 Git 信息，改动呈现为未提交变更，不自动提交/推送/部署。中断后从同一按钮或待确认提示进入核对恢复，原项目和核对副本都会保留。应用失败/恢复后可下载结果，也可解决源项目问题后显式再次应用；每次使用新操作 ID，旧请求有围栏，刷新不重写文件。

独立侧栏“协作任务”入口已移除。任务从空间中的对话消息查看，异常状态可通过消息内“更多操作”进入管理面板；未伪造旧任务的来源线程。实现边界与验证见[空间内协作方案](architecture/collaboration-in-chat.md#当前实现与验收边界)。

新增 API：`GET /sessions/{id}/collaboration/context?thread=&include=`、`GET /sessions/{id}/collaboration/repositories`、`GET /collaboration/runs?session=&thread=`；创建体可携带服务端返回的 `context`。`supplement` 动作 payload 为 `{text}`。结果应用使用 `PUT /collaboration/runs/{run}/application/{action}`，请求为 `scope/expected_revision/snapshot_id`；`GET …/application` 查询，`POST …/application/recover` 携带 `scope/action_id` 显式恢复。应用与查询使用原有属主鉴权，不允许跨空间写入。

## 启用与创建

在测试实例 `config.json` 中设置 `"collaboration_enabled": true` 并重启服务，登录后进入工作空间，在输入框选择“多 Agent 协作”。不需要把源空间的 Agent 类型作为主辅限制；两角色各自选择可用账号、Claude Code 或 Codex、模型与推理强度，支持跨类型和同类型组合。“交换主辅”交换整套角色配置。

源空间必须包含普通、干净的 Git 仓库，填写空间内相对路径，默认 `.`。预检冻结 HEAD，执行导入时再次检查。当前拒绝未提交内容、submodule、LFS 指针、危险链接及项目 CLI 扩展配置（含子目录中的 MCP、hooks、技能/插件配置）；Markdown 项目说明可以保留。单份快照上限 128 MiB / 10000 条目；每任务登记产物总量上限 512 MiB，仍受实例存储配额约束。

提交需求后主方规划，默认先等用户确认计划；勾选“规划后自动执行”则省去该确认。辅方执行，遇到问题先交给主方，必要时主方转问用户。辅方提交快照后先执行平台验证，再将同一快照的验证证据交给主方评审、要求有限返工。各角色用独立 home 和原生线程，角色调整创建新的配置代际和上下文，不把一种 CLI 的会话 ID 交给另一种 CLI。

## 控制、费用与交付

- “本步结束后暂停”等待当前回合完成。暂停后可更换主辅、账号、模型、强度及任务限额；旧参与者停止后才能切换。
- “仅修复交接格式”保留已执行工作和费用，在同一参与者上下文中用只读快照补写交接 JSON，不重开可写实施步骤。
- “取消任务”会请求停止。已产生的文件和费用不回滚；进程/历史/用量结果不明时需核对，不能直接当作未执行而重跑。
- 异常任务通过“核对运行结果”先停止并核验参与者，生成单独的核对副本，展示其文件差异和运行记录。核对副本可下载，但不成为可交付结果；勾选确认后仍需重新配置并规划。
- “删除任务和副本”需要任务已暂停、取消或结束；运行中先暂停/取消，未确定回合先核对。删除先留下持久围栏、撤销正文/产物访问，再清参与者容器、home、工作树、快照及当前工具存储中的私有缓存。清理失败的删除任务留在列表，可重试；费用流水和请求标识保留。
- 创建或操作响应丢失时，刷新和“查询待确认操作”只查原 ID。“放弃未接收操作”只对服务端未接受的 ID 建立围栏，不等价于取消正在运行的任务。
- 费用使用原有回合结算。预算、最多模型步骤和返工次数在步骤边界控制，无法保证正在进行的回合绝不超过金额；未定价/结算缺失不能作为零费用放行有预算的任务。
- “评审通过，结果待应用”表示结果保留在独立快照。下载为 ZIP，不会自动覆盖源项目、合并、推送或部署。“查看文件变更”展示新增、删除、内容、模式和链接变化，可打开文本差异；二进制或大文件通过下载查看。

单步超时默认 1800 秒，累计模型步骤执行预算默认 21600 秒，等待用户答复/计划确认默认 604800 秒；创建或重新配置时可调整。等待到期只暂停，不删文件、不自动答复。进程未知的崩溃回合按该回合配置的单步时限计入时间预算，避免把离线等待天数当作模型执行时间。预算不包括用户等待，正在运行的步骤同时受剩余总时长约束。

实时输出使用只读 SSE，断线时历史与状态继续轮询；连接恢复不会重新提交模型请求。

## 平台验证

可在创建时填写验证命令，例如 `go test ./...`。只有用户配置的命令会被平台执行；模型在正文中声称测试通过不等于平台验证通过。

验证在主方评审之前运行，状态、命令、argv、退出码、输出截断标记、耗时及快照 ID 持久化，并冻结进评审提示词。失败可进入有限返工，主方不能批准交付失败的验证结果。运行环境：独立 Linux 容器、无网络、无账号凭证、不可写根文件系统，只挂载结果快照的可写副本，固定 10 分钟超时、512 MiB 内存、1 CPU、64 PID。所需依赖必须已经在镜像或项目中，无法临时联网安装。输出有界并显示在任务记录中。

验证结束后先移除容器，再核对原有文件、目录和链接：改动或删除原路径则验证失败。新增构建文件只允许位于 `build/`、`dist/`、`out/`、`target/`、`coverage/`、`.cache/`；这些目录中已有的文件也不能改动。新文件仅存在于临时副本，随清理删除，不并入交付。退出非零、未知执行状态或文件核对失败都不能交付。没有配置命令时，页面明确标识“仅模型评审”。

服务重启或清理失败后，不会自动再跑项目脚本。用户重新配置或取消时，服务端先检查持久化的 helper 身份并确认容器清理；原结果记为失败/未知，不冒充通过。即使配置内容相同，验证失败后的显式重新配置也会建立新代际重新规划。

## 重启、备份与兼容

普通重启将未确认执行标为待核对，已排队任务暂停；不会自动补跑模型。浏览器操作范围包含实例和用户创建身份，同名用户重建不继承旧操作。

备份恢复必须使用项目既有恢复工具，目标是新目录：

- full 备份保留项目、快照与历史；恢复副本解绑旧实例容器和 provider 会话。未结束任务需要重新配置；可能执行过的步骤仍须先核对。新参与者不会接管或停止原实例的容器。
- system 备份不包含项目文件。恢复后的协作任务标为 `failed / artifacts_missing`，不再展示为可交付；需要重新取得源码并创建任务。
- 新实例接纳未来操作的 scope 在启动时更新并留下审计；原创建输入、请求 ID、历史和费用保持归属。旧页面不能携旧 scope 操作新实例。

当前工作树为 schema 17（新增终端用量推理强度），上一生产开发预览为 schema 16。schema 12 升级测试覆盖既有聊天回执和空间保留；升级数据库后不能直接用不支持该 schema 的旧二进制运行。协作入口关闭也不代表数据库回退，回滚按既有备份/发布恢复流程处理。

## API 与验证入口

API 前缀 `/api/collaboration`，需要原有登录授权。`options` 返回可用角色绑定选项和当前 scope；`preflight` 检查源码；`PUT /runs/{request_id}` 创建；`GET /runs/{id}` 查询；`GET /runs/{id}/events?after={seq}` 每页至多 100 条，按最后序号继续读取；`PUT /runs/{id}/actions/{action_id}` 提交带 `scope`、`expected_revision` 的动作。请求 ID 和动作 ID 为 32 位小写十六进制字符串，重放必须使用完全相同的冻结输入。

动作包括 `confirm_plan`、`pause`、`resume`、`configure`、`answer`、`review`、`cancel`、`repair_handoff`。答复使用任务当前的 `pending_question`，不能从历史问题自行推断。动作查询与未接受 ID 放弃入口用于失联恢复，不产生新执行资格。完成后的 `GET /runs/{id}/download` 校验快照摘要再提供 ZIP。

其他接口：

| 接口 | 用途 |
| --- | --- |
| `GET /runs/{id}/diff?snapshot=&path=` | 基线与当前/指定快照的清单、文本差异；快照参数固定所见版本 |
| `GET /runs/{id}/stream` | 带 Bearer 登录头的只读 SSE；有界、可丢弃的实时增量 |
| `GET /runs/{id}/steps/{step}/history?after=` | 属主限定的参与者转录字节游标；不开放普通 Session 入口，超大事件在预览中明确省略 |
| `POST /runs/{id}/inspection` | 带 scope/revision，在异常任务停止确认后发布仅供人工核对的工作树快照 |
| `GET /runs/{id}/download?snapshot=` | 仅指定 inspection 产物可在任务未完成时下载，不视为交付 |
| `DELETE /runs/{id}` | 带 scope/expected_revision，清理静止任务；删除围栏后的清理可重试 |

辅助容器和参与者共用启动容量闸门，支持只有一个运行名额；未知残留 helper 仍计入容量，缺属主标签时保守计入用户准入。源空间占满唯一名额时，先停止源空间再预检。

本地检查用 `python3 scripts/verify.py run quick`。浏览器入口 `browser.collaboration` / `webkit.collaboration` 使用合成 API；`docker.collaboration-runtime` 在单容器额度下覆盖四种组合和答疑、验证返工、交接补写、暂停、预算、撤权、用量缺失与取消；使用真实 HTTP/后台调度/SQLite/文件和合成 Docker/CLI。`docker.collaboration-browser` / `docker.collaboration-browser-webkit` 将 Chromium / WebKit 页面接到同一真实 Linux 后端，覆盖创建、交换/重新配置、计划确认、验证/评审、差异、下载、刷新和删除，同时核对执行次数与账本；`docker.collaboration-import` 与 `docker.collaboration-mounts` 检查真实离线 Docker。以上都不调用真实 provider，也不能替代付费模型、真实凭证轮换与候选版本验收。

## 协作工作台与画布演进

### 最终结果与运行记录

已完成任务在对话卡片和详情顶部显示“最终结果”：已获评审批准的执行摘要、完成项、评审确认和独立的平台验证证据。执行方自报的测试放在“执行方报告的检查”中，不代替平台验证。尚未加载齐当前版本的记录时会提示同步，不显示旧一轮结果。

“步骤输出”用于查看过程，可以切换规划、执行、评审等步骤。运行时接收增量文字，结束或刷新后读取已保存的对应回合输出；没有内容、加载中或读取失败都有提示。查看、切换和刷新均不重新调用模型。实现及生产复验见[输出展示修复](milestones/collaboration-output-20261011.md)。

默认新建页只显示任务需求、源工作空间、默认 Agent 组合和“开始协作”。工作空间默认选中当前空间，主辅使用可用账号的默认模型；只有一种 Agent 的账号时，两角色自动使用该类型。展开“协作设置”才显示主辅交换、账号、模型、推理强度、仓库相对路径、验证命令和自动执行；预算与超时再按需展开。自动执行仍默认关闭。

运行后默认进入“任务进度”。等待确认时直接展示计划和确认按钮，等待答复时只展示服务端当前问题及输入框；问题变化清空旧答复。完成时突出下载和文件变更。取消、删除等收进“更多操作”，配置应用留在设置区；删除与异常核对仍要求原来的显式确认。关键状态出现会返回进度视图，避免用户在流程图里看不到待答内容。

协作详情占满当前工作区，在“过程、步骤输出、最终结果、文件与记录”之间直接切换。默认时序图合并同一步骤的状态记录，用户、决策、主 Agent、辅 Agent、平台各有泳道，真实派发、问答、交接与返工按实际发生顺序连线；也可展开全部事件。每步 Token、费用、耗时对齐展示，点击查看输入、输出、缓存读写及结算状态。未知费用和用量不会显示为零，Jev 决策费用单列。手机首次打开使用紧凑事件列表，也可切换横向时序。搜索、历史回放和视图切换不提交动作、不重跑模型。轮询保留既有事件节点和用户选择。

节点按实际尺寸保持正圆；光点与箭头共用路径，正向、反向和自环均按完整折线运动，重放等待当前箭头走完再推进。需求右对齐并标注“你 · 任务需求”，团队回复左对齐并标注主辅模型，不再使用外层竖线和卡框。

当前轨迹支持只读回放、暂停和拖动位置；回放冻结已有记录并隐藏当前结算数字，返回最新后恢复账本数据。开始与结束使用各自真实事件时间，纵向间距不代表耗时。没有记录的 Jev 请求耗时或置信度不补造。本次改变展示，不包含拖拽编排、任意依赖图或并行 worker；后台仍使用双角色串行调度。实现与验收见[轨迹改版记录](milestones/collaboration-trace-20261011.md)及[紧凑工作区改版记录](milestones/collaboration-compact-20261012.md)。
